# CUDA Core 整数族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。文中"实测"来自本机约 70 个校准探针（26 个 opcode 的代表形态 O0/O3 全量反汇编、div/rem 专项、基线脚手架对照）与已建成旗舰套件 `mad/thor_ptx90/`（35 syntax + 43 expanded case，O0–O3 共 312 次编译/归属，9 个带诊断锚定的负向探针）的全量自检。校准探针在会话 scratchpad；套件可完整重现 `mad` 的全部结论，其余 opcode 的结论以探针记录为证据，待建套件复现。
> 设计基线：`01_tcgen05` 的静态实验分层与 `02_tma/实验设计.md` 的文档结构，逐条吸收 `01_tcgen05/对抗式审查_实验设计缺口.md` 的 P0/P1 结论；流程与检查单见 `00_shared/templates/建族套件指南.md`。

## 结论

本族 26 个 opcode 的 PTX→SASS 结构分四类，与 tcgen05 的 A/B/C/D 不同构——本族没有异步协议，取而代之的核心现象是**归一化**：ptxas 把大量不同的 PTX opcode 收敛到极少数 SASS 骨干指令（`IADD3`/`IMAD`/`LOP3.LUT`/`SHF`/`ISETP`/`SEL`/`IMNMX`），映射的信息量主要在操作数形态与修饰符，而不在助记符选择。

| 类别 | 指令（32-bit 代表形态） | PTX→SASS 结构 |
|---|---|---|
| A 归一直译 | `add`/`sub`/`neg`→`IADD3`，`mul.lo`→`IMAD`（RZ 累加槽技巧），`mul.hi`→`IMAD.HI[.U32]`，`mul.wide`→`IMAD.WIDE[.U32]`，`mad.lo`→`IMAD`，`and`/`or`/`xor`/`not`→`LOP3.LUT`（immLut 0xc0/0xfc/0x3c/0x33），`shl`/`shr`→`SHF.L/R` 变体，`shf.l/r.clamp/wrap`→`SHF`（`.W` 区分 wrap），`min`/`max`→`IMNMX`（**符号性进助记符 `.U32`，min/max 由第三谓词操作数极性 `PT`/`!PT` 区分**），`abs.s32`→`IABS`（专用单指令） | 1 条 PTX → 1 条 SASS |
| A′ 固定多指令组合 | 64-bit 的 add/sub/neg（`IADD3`+`IADD3.X` 进位对）、`shl.b64`/`shr.s64`（双 `SHF` 对）、`not.b64`（双 `LOP3`）、`mul.wide.s32/u32` 后接 64-bit 累加的 `mad.wide`（`IMAD.WIDE`+`IADD3`+`IADD3.X`）、`addc`/`subc`/`madc` 进位链（`IADD3.X`/`IMAD.WIDE.U32`）、`set`（`ISETP`+`SEL`）、`selp.s64`（双 `ISETP.EX`+双 `SEL`） | 1 条 PTX → 2–5 条固定结构 SASS |
| B 序列/协议类 | `div.u32/s32`、`rem.u32/s32`：17–24 条**内联** Newton-Raphson 序列（锚点 `MUFU.RCP`+`F2I`/`I2F`+`IMAD` 迭代）；`div.s64/u64`、`rem.s64/u64`：68–88 条且含 **`CALL.REL.NOINC` 进入共享例程**（`RET` 返回）——64-bit 除法走 ABI 调用而非内联，是本族唯一出现调用边界的 lowering；`abs.s64`（5 条：取负进位对+`ISETP`+双 `SEL`）、`mad.hi.sat.s32`（6 条：`IMAD.HI`+`IMAD.IADD`+双 `PLOP3.LUT` 溢出检测+双 `SEL` 钳位）、`cnot`（`ISETP.EQ`+`SEL`+取负 [+16-bit 加 `PRMT`]） | 1 条 PTX → 长序列，部分含调用边界 |
| F 折叠类 | `mov` 寄存器形态：零指令（寄存器合并）；`mov` 立即数形态：经 `HFMA2 Rd, -RZ, RZ, imm16, imm16` 习语物化 32-bit 立即数（不是 `MOV`！）；`setp`+`selp` 消费链被模式识别成 `IMNMX`；`selp`/`slct` 被下沉为**谓词化 `LDG`**（`@!P0 LDG.E`——选择被折进两个 producer 的谓词化执行）；`mad`/`mul` 乘数槽为 0/±1 或全常量时代数化简（`IMAD` 消失，见套件 `empty_target_allowed`） | 1 条 PTX → 0 条或改换形态 |

对静态编译器的直接推论：(1) 逆向方向（SASS→PTX）在本族是高度多对一的，`IADD3`/`IMAD` 的一个签名对应多个 PTX opcode，逆向规则只能给候选集；(2) F 类说明**逐指令归属在本族必须允许"合法但零指令/改换形态"结果**，`setp`/`selp`/`slct`/`mov` 的套件设计必须把消费者形态作为一等轴，否则测到的是消费链的模式识别产物而非该指令自身。

## 合法面实测（旗舰套件负向探针，全部带诊断锚定）

| 探针 | 诊断 |
|---|---|
| `mad.wide.{s64,u64}`（wide 只定义到 32-bit） | "Unexpected instruction types specified for 'mad.wide'" |
| `mad.lo.sat.s32` / `mad.lo.sat.u64`（补集） | "Illegal modifier '.sat' for instruction 'mad.lo'" |
| `mad.wide.sat.s32` | "Arguments mismatch for instruction 'mad.wide'" |
| `mad.hi.sat.{u32,s64}` 及补集 `.s16` | "Modifier '.sat' does not apply to '.u32'/'.s64'/'.s16' type" |
| `mad.lo.f32`（浮点混入整数 mode） | "Unexpected instruction types specified for 'mad.lo'" |

`.sat` 的合法面被证实**只有 `mad.hi.sat.s32` 一点**；两条补集抽样（`.hi.sat.s16`、`.lo.sat.u64`）确认边界外系统拒绝且诊断按约束类型分组（mode 类 vs type 类），拒绝可归因。

## 审查缺口对应设计

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | 本族无 scoreboard 语义；P0-1 的对应物按预注记为**操作数槽 × 立即数编码类**：套件对 a/b/c 三槽各设 5 档立即数（0/1/-1/0x7fffffff/0x12345678），实测发现 0/±1 触发代数折叠（`IMAD` 消失）而大立即数改变编码路径——"同一 PTX 语法因操作数值不同而产生不同 SASS 结构"正是 P0-1 精神在 ALU 族的形态，已作为 `empty_target_allowed` 坐标类显式记账而非当作噪声 |
| P0-2 合法面未证伪 | 9 条负向探针全部登记 `expected_diagnostic` 并实测匹配，含 2 条补集抽样；`mad.hi.s32` 物化零发现（见下）本身是"预期语义 vs 实测 lowering"差异经 `hi_accumulate_anchor` 对照 case 固化的证伪流程 |
| P0-3 组合不足 | 立即数多槽组合（`ab_imm_combo`/`bc_imm_combo`/`abc_imm_all`）显式进 syntax 矩阵；expanded 含 `dual_mad_slot_reuse`（双 mad 槽位复用）；基线零命中检查用去目标脚手架在 O0–O3 实测 `IMAD`/`LEA.HI` 零命中（含 5 档立即数替身），未收窄 pattern 或 O 档 |
| P1-1 模板未受控 | expanded 含 `template_wide`（签名加宽 + pad 参数乱序） |
| P1-2 重物化前提 | a/b/c 三槽各有 `producer_indirect` case（内存装载 + 不可折叠加法） |
| P2 边界 | 套件接受 `--ptxas/--nvdisasm` 路径参数；`mad.hi.s32` 物化零行为已在 sm_80/90a/100a/110a 四架构探针交叉确认为跨版本稳定（该结论证据级为探针观察，未入套件矩阵） |

## 旗舰发现：`mad.hi.{s32,u32}` 的 c 操作数不参与累加

非 sat 的 32-bit `mad.hi` 被 lower 成第三槽为物化零的单条 `IMAD.HI`——c 的 global 装载保留（未被判死），但从不进入乘加。对照：`mad.hi.sat.s32`、`mad.hi.{s64,u64}`、16-bit `mad.hi`（经 `LEA.HI`）都正确折入 c。套件用 `hi_accumulate_anchor` case（c 另行独立落地使其装载不可消除）在矩阵内复现，排除探针伪象。**对生成正确 SASS 的编译器，这是必须逐字节复刻的 ptxas 行为还是必须修复的偏差，属于语义裁决，本文只登记静态事实**；运行时数值验证归 P2-2 边界。

## 各指令研究重点

- `mad`（`FRAMEWORK_VALIDATED`）：套件见 [mad/thor_ptx90/](mad/thor_ptx90/)；后续轴是 16-bit 形态的 `LEA.HI` 编码细节与 `dual_mad` 在寄存器压力下的槽位行为。
- `add`/`sub`/`mul`/`min`/`max`/`abs`/`neg`（`DESIGNED`，A/A′ 类）：套件可直接复用 mad 的结构；重点是 64-bit 进位对的 `P0` 谓词分配与 16-bit 的 `PRMT` 规范化条件。
- `and`/`or`/`xor`/`not`/`cnot`（`DESIGNED`）：immLut 值域与 `14_bit_ops/lop3` 套件交叉核对（那边持有 immLut 透传规则），本族只需覆盖"命名逻辑 op → 固定 immLut"映射。
- `shl`/`shr`/`shf`（`DESIGNED`）：重点是 `.HI`/`.W` 修饰符组合与 b64 双条结构中移位量 >32 的路径。
- `set`/`setp`/`selp`/`slct`（`DESIGNED`，F 类风险最高）：**必须以消费者形态为主轴**（孤立 / 接算术 / 接 select / 接分支），否则测得的是消费链模式识别；`slct` 与 `selp` 的谓词化 `LDG` 下沉需要专门的归属方法（目标指令可能变成带 `@P` 的 producer）。
- `div`/`rem`（`DESIGNED`，B 类）：32-bit 内联序列按 tcgen05 B 类方法建序列模板表（`MUFU.RCP` 锚点、迭代结构、符号处理差分）；64-bit 的 `CALL` 例程需要先解决"共享例程归属"方法论（多个 div 共用一份例程体）。
- `addc`/`subc`/`madc`（`DESIGNED`）：进位链跨指令配对（`IADD3.X` 消费前条 `P0`），归属单元是链不是单指令——同 tcgen05 P0-3 的序列裁决。
- `mov`（`DESIGNED`，F 类）：寄存器形态零指令、立即数形态 `HFMA2` 习语，套件需用 `empty_target_allowed` 全放行并把观测量换成立即数物化方式。

## STATIC_ONLY 边界声明

本文与套件的全部结论限于静态编译与反汇编：指令选择、操作数形态、立即数编码类、折叠条件。`mad.hi` 物化零的数值语义、div/rem 序列的舍入与边界值行为、饱和钳位的实际数值，都需要运行时 oracle，不在本轮 PASS 含义内。
