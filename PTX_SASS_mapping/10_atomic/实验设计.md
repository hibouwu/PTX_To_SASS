# Atomic 与 reduction 族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。文中"实测"来自本机校准探针（op × type 全枚举、atom/red 正反对照、sem × scope 抽样、地址形态对照）与已建成旗舰套件 `atom.global/thor_ptx90/`（28 syntax + 24 expanded case，O0–O3 共 208 次编译/归属，11 个带诊断锚定的负向探针）的全量自检。探针在会话 scratchpad；套件 `suite_spec.py` 的文档字符串同步记载校准结论。
> 设计基线：`01_tcgen05` 的静态实验分层与 `02_tma/实验设计.md` 的文档结构，逐条吸收 `01_tcgen05/对抗式审查_实验设计缺口.md` 的 P0/P1 结论。

## 结论

本族的核心映射不是"opcode → 助记符"而是三条**由使用形态决定的改写规则**，每条都已用正反对照探针固化：

1. **死结果降级**：`atom.global.<op>` 的目的寄存器死亡时，ptxas 把 `ATOMG` 静默降级为 `REDG`——对每个有 `red` 对应物的 op（add/min/max/and/or/xor/inc/dec）都成立；`exch`/`cas` 没有 `red` 形态（`red.global.exch/cas` 实测拒绝 "Illegal operation"），死结果时保留 `ATOMG` 并把目的改写为 `RZ`。反向对照：显式 `red.global.<op>` 编译出与死结果降级**逐字节相同**的 `REDG`。推论：`atom` 与 `red` 在 SASS 层是同一机制的两个入口，逆向映射必须给候选集。
2. **uniform 地址聚合改写**：地址为参数直取（warp 内 uniform）时，O3 在同一 `ATOMG` 周围加 `VOTEU`/`POPC`/`SHFL` 聚合脚手架（warp 内合并原子操作）；地址按 `%tid` 派生（逐 lane 不同）则是裸 `ATOMG`。**同一条 PTX，地址来源的 uniformity 改变整个 lowering 结构**——这是 tcgen05 P0-3"决策单元是区域"在本族的形态，套件因此把地址形态定为一等因子。
3. **标量 f16 合成**：标量 `f16` 的 add 没有原生原子指令，经 CAS 循环合成（套件 `scalar_f16_add_cas_synthesis` CTX）；packed `f16x2`/`bf16x2` 有原生形态。

## 实测助记符总表

| PTX 因素 | SASS 结果 |
|---|---|
| `atom.global.<op>.<ty>`（结果存活） | `ATOMG.E.<OP>[.类型后缀][.STRONG.<SCOPE>]` |
| `atom.global.<op>.<ty>`（结果死亡，op 有 red 对应物） | `REDG.E.<OP>...`（降级） |
| `red.global.<op>.<ty>` | `REDG`（与降级形态逐字节相同） |
| `exch`/`cas` 结果死亡 | 保留 `ATOMG`，目的 `RZ` |
| scope 映射 | 无/`.cluster`/`.gpu` → GPU 档（缺省不加后缀或 `.STRONG.GPU`）；`.cta` → SM 档；`.sys` → SYS 档 |
| `.release`/`.acq_rel` | 在 `ATOMG/REDG` 前**加发 `MEMBAR.ALL.<scope>`** |
| `.relaxed`/`.acquire` | 不产生额外指令（与裸形态同） |
| 地址 uniform（参数直取） | `VOTEU`+`POPC`+`SHFL` 聚合脚手架 + `ATOMG` |
| `cas.b32` | `ATOMG.E.CAS`，比较/交换双源操作数 |
| packed `f16x2`/`bf16x2` add（`.noftz`） | 原生 `ATOMG.E.ADD` 打包形态 |
| 向量 fp16 min/max（v2/v4/v8） | 原生向量形态（v3 非法，见负向） |

已校准 op × type 合法面（28 组合，超出者全部带诊断拒绝）：

| op | 合法类型 |
|---|---|
| add | u32 u64 s32 f32 f64 f16x2 bf16x2（浮点带 `.noftz`；标量 f16 经 CAS 合成路径另计） |
| min / max | u32 u64 s32 s64 |
| and / or / xor | b32 b64 |
| exch | b32 b64 |
| cas | b32 b64 **b16**（b16 是易漏的合法点） |
| inc / dec | 仅 u32 |

## 合法面实测（负向探针，全部带诊断锚定）

| 探针 | 诊断 |
|---|---|
| `and.u32` / `exch.u32` / `add.b32` / `min.f32` / `inc.s32` / `dec.b64` | 每类各自独立诊断（"Operation .and requires .b32 or .b64 type"、"Operation .exch requires .b32 or .b64 or .b128 type"、"Operation .inc requires .u32 type" 等——**op×type 约束的诊断按 op 分组，拒绝可归因**） |
| `cas` 缺交换操作数 | "Arguments mismatch for instruction 'atom'" |
| `.acquire.release` 分写（≠`.acq_rel`） | "Duplicate .release modifier" |
| 补集：`.mmio` 修饰符 | "Illegal modifier '.mmio' for instruction 'atom'" |
| 补集：`.weak` 内存序 | "Illegal modifier '.weak' for instruction 'atom'" |
| 补集：`.v3.f16` 向量宽度 | "Illegal vector size: 3" |

## 审查缺口对应设计

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | 访存原子指令有 scoreboard 语义：expanded 含 `inflight_depth_2_distinct_address`（双地址在飞）与 `dual_atom_same_address`（同址串行依赖）；runtime 保留全函数 128-bit 编码供控制字差分 |
| P0-2 合法面未证伪 | 11 条负向探针全带 `expected_diagnostic` 且按约束类型分组；3 条补集抽样（`.mmio`/`.weak`/`.v3`）在假定合法面之外系统采样；`cas.b16` 与向量 fp16 min/max 是"预期外合法"发现并入正向矩阵 |
| P0-3 组合不足 | sem × scope 做 t=2 组合抽样（6 个 CTX 组合而非单因素）；死结果 × op 做 7 档对照（每个降级类 op 一组）；地址形态 × uniformity 是结构性组合轴 |
| P1-1 模板未受控 | expanded 含 `template_wide`（pad 参数乱序签名） |
| P1-2 重物化前提 | 地址与值各有 indirect producer CTX（`address_indirect_producer`/`value_indirect_producer`） |
| P2 边界 | 套件接受 `--ptxas/--nvdisasm` 路径参数；聚合改写（VOTEU 脚手架）是最可能随 ptxas 版本漂移的部分，跨版本重跑优先复核 |

## 各目录研究重点

- `atom.global`（`FRAMEWORK_VALIDATED`）：套件见 [atom.global/thor_ptx90/](atom.global/thor_ptx90/)；后续轴是 `.mmio` 在其他 order/scope 组合下的合法性完整枚举与 b128 exch 的支持面。
- `red.global`（`DESIGNED`）：核心结论已由正反对照固化（`red` ≡ 死结果 `atom` 降级）；套件价值在于独立验证 `red` 自己的 sem/scope 面与 `red` 不存在的 op（exch/cas）的诊断。
- `atom.shared` / `red.shared`（`DESIGNED`）：预计 `ATOMS`/`REDS` 家族（tcgen05 alloc 序列中已见 `ATOMS.OR` 旁证）；shared 版本没有 `.E` 描述符寻址，地址形态轴需重设计；scope 面比 global 窄（无 sys？），待枚举。
- generic 地址 atom（无 `.global` 后缀）：归 `atom.global` 目录的扩展轴——地址空间判定是运行时序列还是静态直译，待专项探针。
