# CUDA Core 浮点与转换族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。文中"实测"全部来自本机 scratchpad 一次性探针脚本（约 90 个独立 kernel，覆盖字面量写法、舍入/FTZ/SAT 修饰符全笛卡尔积、abs/neg 折叠、min/max 修饰符、七个特殊函数的 approx/rn 形态、div 全形态、cvt 抽样）的 O0/O3 `ptxas` 编译与 `nvdisasm --print-code --print-instruction-encoding` 反汇编，以及已建成的 `fma/thor_ptx90/` 套件（20 syntax + 77 expanded case，O0–O3 共 388 次编译/归属，10 负向探针）的全量自检。规范阅读得出的预期与实测冲突处，本文以实测为准并显式标注冲突（P0-2 证伪记录）。
> 设计基线：`00_shared/templates/建族套件指南.md` 的流程规范，质量标准源自 `01_tcgen05/对抗式审查_实验设计缺口.md`，结构范例是 `02_tma/实验设计.md`。

## 结论

本族 17 个 opcode 目录不共享同一套"opcode+qualifier→助记符"直译模型。按 PTX 指令与 SASS 的结构关系，实测把它们分成四类，套用 tcgen05 审查引入的分类法并按本族语义重新定义边界：

| 类别 | 判据 | 代表指令 |
|---|---|---|
| **直译**（1 PTX → 1 SASS，qualifier 逐个映射到 mnemonic 后缀或操作数修饰符） | 单条指令、无编译期分支 | `add`/`sub`/`mul`/`fma` 的 rn 形态、`min`/`max`（f32）、approx.ftz 形态的 `rcp`/`sqrt`/`rsqrt`/`lg2`/`ex2`（单条 `MUFU.*`）、绝大多数 `cvt` 抽样点 |
| **MUFU**（直译的子类，专指落到 Turing 系遗留的近似函数单元） | 单条 `MUFU.{RCP,SQRT,RSQ,LG2,EX2,SIN,COS}` 或 `.64H` 变体 | `rcp.approx.ftz`、`sqrt.approx.ftz`、`rsqrt.approx.ftz`、`lg2.approx.ftz`、`ex2.approx.ftz`（f32/f64 皆有 `.64H` 双精度头字变体） |
| **序列**（1 PTX → 编译期固定的多指令序列，序列结构本身是研究对象；含"短序列"和"B 类长序列"两个子档） | 无 approx.ftz 的近似形态（denormal/overflow 缩放短序列）；`.rn`/`.rz`/`.rm`/`.rp` 全精度形态（含内联子程序调用的长序列）；f64 `min`/`max`（`DSETP`+`SEL`+`FSEL`+`LOP3`） | `rcp.approx.f32`（无 ftz，4 条）、`rcp.rn.f32`（80 条，含 `CALL`/`RET`）、`div.rn.f64`（144 条）、`min.f64`/`max.f64`（7 条） |
| **折叠**（PTX 指令本身不产生独立 SASS opcode，作为消费者指令的源操作数修饰符或退化实现被吸收） | 无消费者时退化成 dummy 直译；有消费者时完全消失于消费者的修饰符位 | `abs`/`neg`（`|Ra|`/`-Ra` 源修饰符，或无消费者时的 `FADD |x|,-RZ`）、`sub`（恒为 `add` 的第二操作数取负）、`cvt.f32.f16`（widening，折叠进 `HADD2.F32` 而非任何 `F2F*` 转换单元） |

这与 `02_tma` 的"A/C 两类即可覆盖全族"不同——本族因为浮点近似/全精度对偶（approx vs rn）和跨字长退化实现（min/max f64、cvt.f32.f16）天然产生序列类和折叠类，且折叠类的成因（无编译期支持的独立操作码）与 tcgen05 D 类（零指令调度约束）不同源：D 类是协议指令被优化消除，本族折叠类是这些 PTX 操作码本来就没有对应硬件功能单元，只能表达为其他指令的操作数修饰符。

## 探针校准表

### add / sub / mul / fma（f32 / f64，rounding）

| PTX | 舍入是否可省略 | `.rn` SASS 后缀 | `.rz`/`.rm`/`.rp` SASS 后缀 | 备注 |
|---|---|---|---|---|
| `add{.rnd}.f32/f64` | **可省略**，省略即隐含 `.rn` | 无后缀（`FADD`/`DADD`） | `.RZ`/`.RM`/`.RP` | probe:add_rounding |
| `mul{.rnd}.f32/f64` | 可省略 | 无后缀（`FMUL`/`DMUL`） | `.RZ`/`.RM`/`.RP` | probe:mul_rounding |
| `sub{.rnd}.f32/f64` | 可省略 | **不存在独立 SASS opcode**：恒等于 `add` 且第二操作数取负（`FADD Rd,Ra,-Rb`，仅符号位翻转，编码与 `add` 只差最高位） | 同上，`-Rb` 前追加 `.RZ` 等 | probe:sub_lowers_to_add——折叠类的一个特例，因为它不是操作数修饰符折叠而是"指令本身不存在" |
| `fma.rnd{.ftz}{.sat}.f32` / `fma.rnd.f64` | **不可省略**，省略即 `ptxas` 报错 `Rounding modifier required for instruction 'fma'` | 无后缀（`FFMA`/`DFMA`） | `.RZ`/`.RM`/`.RP` | probe:fma_rounding + `fma/thor_ptx90` 套件正向覆盖 |

`.ftz`、`.sat` 只在 `.f32` 合法；`.f64` 上两者均被拒绝，诊断分别是 `Illegal modifier '.ftz' for instruction '<op>'` 和 `Illegal modifier '.sat' for instruction '<op>'`（`add`/`fma` 均实测）。四档 `rnd` 与 `.ftz`/`.sat` 在 f32 上自由组合，SASS 后缀按声明顺序追加（`FFMA.FTZ.SAT`、`FFMA.RP.FTZ`）——**但 PTX 侧修饰符书写顺序不是规范化的**：`fma.f32.rn`、`fma.ftz.rn.f32`、`fma.sat.rn.f32` 均被接受且产生与规范拼写完全相同的 SASS（probe，已被推翻的假设：修饰符必须按 `rnd.ftz.sat.type` 顺序书写）。

`fma` 操作数位**不接受**直接的 `-%reg`/`|%reg|` 内联写法（`Operand negation not allowed for instruction 'fma'`），这与下面 abs/neg 折叠一节的机制是两条不同路径：折叠只能通过一条独立的 `neg.f32`/`abs.f32` PTX 指令实现，永远不能写进 `fma` 的操作数列表里。`add`/`mul` 未见此限制以外的信息（未逐一探测，留 DESIGNED）。

`fma.rn.f16`/`fma.rn.bf16`（打包半精度标量）在本目录**确实合法**，产生 `HFMA2`/`HFMA2.BF16_V2`（用 `.H0_H0` 选择器把标量广播进打包槽位）——这是 P0-2 补集抽样的发现：任务原假设"`fma.f16` 在本目录非法，应归 `11_half_precision`"被实测推翻；正确表述是"`fma.f16` 合法但不产生 `FFMA`/`DFMA`，不落在本目录的 target_patterns 内，语义研究仍归 `11_half_precision`/`12_bf16`"。

### min / max（NaN 语义修饰符）

| PTX | SASS | 备注 |
|---|---|---|
| `min.f32 d,a,b` | `FMNMX d,a,b,PT` | `min`/`max` 共享同一 `FMNMX` opcode，仅末尾谓词操作数取反区分：`min`→`PT`，`max`→`!PT` |
| `max.f32 d,a,b` | `FMNMX d,a,b,!PT` | 同上 |
| `min.ftz.f32` | `FMNMX.FTZ ...,PT` | `.ftz` 合法（f32） |
| `min.NaN.f32` | `FMNMX.NAN ...,PT` | `.NaN` 合法（f32），可与 `.ftz` 组合（`FMNMX.FTZ.NAN`） |
| `min.abs.f32`（不带 `.xorsign`） | **拒绝**：`Modifier '.abs' requires modifier '.xorsign'` | 已被推翻的假设：`.abs` 是独立可选修饰符；实测它必须与 `.xorsign` 成对出现 |
| `min.xorsign.abs.f32` | `FMNMX.XORSIGN d,|a|,|b|,PT` | `.xorsign.abs` 恒成对，产生一个 `.XORSIGN` 后缀并把两个源操作数都套 `||` | 
| `min.xorsign.f32`（不带 `.abs`） | **拒绝**：`Modifier '.xorsign' requires modifier '.abs'` | 双向互相要求，二者是同一个语法单元的两半 |
| `min.f64` / `max.f64` | **不是单条指令**：`DSETP.{MIN,MAX}.AND P0,P1,Ra,Rb,PT` 定谓词 → `SEL` 选低 32 位 → `FSEL` 选高 32 位数值部分 → `@P1 LOP3.LUT` 处理 NaN/符号边界的高位修正，共 4 条目标序列 | probe:min_max_f64_sequence——序列类，f64 上没有 `.ftz`/`.NaN`/`.xorsign.abs`（全部因缺少对应单指令而被 `ptxas` 拒绝，诊断同 f32 的"Illegal modifier"模式） |

`min`/`max` 尚未建套件（见路线图），此表用于其 `DESIGNED` 阶段的轴校准。

### abs / neg（折叠）

| 场景 | SASS | 备注 |
|---|---|---|
| `abs.f32 %fo,%f0;`（无消费者，直接落到 `st.global`） | `FADD Rd,|Ra|,-RZ` | 没有 `FABS` opcode；`ptxas` 用"对 `-0` 做绝对值加法"合成一个语义等价的 `FADD` | 
| `neg.f32 %fo,%f0;`（同上） | `FADD Rd,-Ra,-RZ` | 没有 `FNEG` opcode，同样退化为 `FADD` |
| `abs.f64`/`neg.f64`（同上） | `DADD Rd,-RZ,|Ra|` / `DADD Rd,-RZ,-Ra` | f64 同构，退化为 `DADD` |
| `abs.f32 %t,%f0; add.f32 %fo,%t,%f1;` | `FADD Rd,|Ra|,Rb` | 有真消费者时，`abs`/`neg` 完全消失，只留源操作数修饰符 |
| `neg.f64 %t,%d0; fma.rn.f64 %do,%t,%d1,%d2;` | `DFMA Rd,-Ra,Rb,Rc` | 折叠可以跨到 `fma`（尽管 `fma` 语法本身不接受内联 `-`） |
| `abs.f64 %t,%d0; neg.f64 %t,%t; add.f32...`（先 abs 后 neg） | `FADD Rd,-|Ra|,Rb` | 双重折叠可叠加为 `-|Ra|` |
| `abs.ftz.f64` / `neg.ftz.f64`（f64 加 `.ftz`） | **拒绝**：`Illegal modifier '.ftz' for instruction 'abs'/'neg'` | 与 add/mul/fma 同一模式，`.ftz` 只对 f32 合法 |

`abs`/`neg` 没有独立 `DESIGNED`/套件计划——它们的完整语义只能在"折叠进某条消费者指令"的上下文里研究，已并入 `fma` 套件的 `fold_*` expanded 轴，并会在其余算术类套件（`add`/`sub`/`mul`）建设时复用同一模式。

### rcp / sqrt / rsqrt / lg2 / ex2 / sin / cos（近似与全精度）

approx 家族（f32 全部实测，f64 见下表逐指令标注）：

| PTX | ftz 关闭 | ftz 开启 |
|---|---|---|
| `rcp.approx{.ftz}.f32` | 短序列（`FSETP` 双向 subnormal/overflow 判定 → 条件缩放 `FSEL` → `MUFU.RCP` → 反缩放 `FMUL`，共 7 条） | `MUFU.RCP` 单条 |
| `sqrt.approx{.ftz}.f32` | 短序列（`FSETP` subnormal 判定 → 条件放大 `FMUL` → `MUFU.SQRT` → 条件缩小 `FMUL`，共 4 条） | `MUFU.SQRT` 单条 |
| `rsqrt.approx{.ftz}.f32` | 同 `sqrt` 结构（4 条） | `MUFU.RSQ` 单条 |
| `lg2.approx{.ftz}.f32` | 同结构（4 条，末尾用 `FADD` 修正指数偏移而非 `FMUL`） | `MUFU.LG2` 单条 |
| `ex2.approx{.ftz}.f32` | 同结构（4 条，判定域值不同：`FSETP.GEU d,-126`） | `MUFU.EX2` 单条 |
| `sin.approx{.ftz}.f32` | `FMUL.RZ`（乘 `1/2π` 做参数归约）→ `MUFU.SIN`，**恒为 2 条，`.ftz` 不改变该结构**（`.ftz` 在 sin/cos 上只影响 `MUFU` 内部行为，不消除参数归约步骤，这与 rcp/sqrt/rsqrt/lg2/ex2 的"ftz 消除缩放步骤"模式不同——已校准的例外） | 同上，恒 2 条 |
| `cos.approx{.ftz}.f32` | 同 `sin`（`MUFU.COS`） | 同上 |

f64 逐指令实测（approx 家族并非在 f64 上对称存在）：

| PTX | 结果 |
|---|---|
| `rcp.approx.f64`（无 `.ftz`） | **拒绝**：`'.ftz' modifier required for instruction 'rcp.approx.f64'`——f64 近似倒数强制要求 `.ftz`，没有非 ftz 形态 |
| `rcp.approx.ftz.f64` | `MUFU.RCP64H` 单条（另有一条 `HFMA2` 清零高位打包寄存器，仍计入"直译/MUFU"类） |
| `sqrt.approx.f64` | **拒绝**：`Illegal modifier '.approx' for instruction 'sqrt'`——f64 平方根**没有**近似形态，只有 `.rn` |
| `rsqrt.approx.f64`（无 `.ftz`） | 合法，但是 **B 类长序列**（104 条，含 `CALL.REL.NOINC $__internal_..._drsqrt_f64_slowpath_v2`） |
| `rsqrt.approx.ftz.f64` | `MUFU.RSQ64H` 单条 |
| `lg2.approx.f64` | **拒绝**：`Unexpected instruction types specified for 'lg2'`——`lg2` 完全不支持 f64（不论 approx 还是 rn） |
| `ex2.approx.f64` | **拒绝**：同上，`ex2` 完全不支持 f64 |
| `sin`/`cos` 任何 f64 形态 | 未探（PTX 语法本身只定义 `.f32`，留 DESIGNED，不预期存在） |

全精度（`.rn`/`.rz`/`.rm`/`.rp`）家族——**只有 `rcp` 和 `sqrt` 拥有该家族**，`rsqrt`/`lg2`/`ex2`/`sin`/`cos` 全部拒绝任何舍入修饰符（诊断统一为 `Illegal rounding modifier for instruction '<op>'`，已逐一探测确认）：

| PTX | 结构（按 tcgen05 B 类归类） |
|---|---|
| `rcp.rn.f32` | 56–80 条：`MUFU.RCP` 给出初始近似 → 两轮 `FFMA` Newton-Raphson 精化 → `CALL.REL.NOINC` 跳到 `$__internal_0_$__cuda_sm20_rcp_rn_f32_slowpath` → 该子程序内做 subnormal/overflow 边界特判、二次 `MUFU.RCP` 与更多 `FFMA` 精化 → `RET.REL.NODEC` 返回主体 |
| `rcp.{rz,rm,rp}.f32` | 同构，`CALL` 目标换成 `..._rcp_{rz,rd,ru}_f32`（PTX `.rm`/`.rp` 对应符号常量名里的 `rd`/`ru`，即 round-down/round-up），72–128 条 |
| `rcp.rn.f64` | 144 条，双 `MUFU.RCP64H` 收敛 + `CALL $__internal_0_$__cuda_sm20_dblrcp_rn_slowpath_v3` |
| `sqrt.rn.f32` | 56 条，`MUFU.RSQ` 起步（用倒数平方根再乘回被开方数得到平方根近似）→ `CALL ..._sqrt_rn_f32_slowpath` |
| `sqrt.{rz,rm,rp}.f32` | 同构，64–72 条 |
| `sqrt.rn.f64` | 144 条，`MUFU.RSQ64H` + `CALL ..._dsqrt_rn_f64_mediumpath_v1`，末段含 `DFMA.RM`/`DFMA.RP` 双向舍入再用 `DSETP.GT` 选择——即全精度平方根内部要同时算出两个方向的候选再选真值 |
| `sqrt.{rz,rm,rp}.f64` | 128 条，`CALL ..._dsqrt_{rz,rd,ru}_f64` |

**关键结构性发现**：这些长序列不是纯内联代码，而是同一 kernel 内对一个 `$__internal_..._slowpath` 符号的真实 `CALL.REL.NOINC` / `RET.REL.NODEC`——即 `ptxas` 把全精度倒数/平方根实现为一个"库函数"风格的子程序调用协议，而不是纯粹展开。这比 `tcgen05.alloc` 的自旋循环内联序列更接近传统函数调用 ABI（保存返回地址寄存器、约定跳转目标），是 B 类协议在本族的具体形态，需要单独的调用点/被调点配对建模（子程序体只出现一次，多个调用点共享）。

### div（全形态）

| PTX | 结果 |
|---|---|
| `div.f32`（无任何修饰符） | **拒绝**：`Rounding modifier or '.approx' modifier required for instruction 'div'` |
| `div.approx.f32`（无 `.ftz`） | 短序列（5 条：`FSETP` subnormal 判定 → 条件缩放 → `MUFU.RCP` → `FMUL`） |
| `div.approx.ftz.f32` | 2 条：`MUFU.RCP` + `FMUL.FTZ` |
| `div.full.f32`（无 `.ftz`） | 8 条：比 `.approx` 多一段 overflow 缩放分支（`FSETP.GT` 判大数 → `FMUL 0.25`） |
| `div.full.ftz.f32` | 5 条，同结构去掉 subnormal 分支 |
| `div.{rn,rz,rm,rp}.f32` | B 类长序列（104–128 条）：`MUFU.RCP` 起步 → `FCHK P0,Ra,Rb`（IEEE 除法专用的"是否需要慢路径"检查指令，仅在 `.rn` 变体出现；`rz`/`rm`/`rp` 直接 `CALL` 不经 `FCHK`）→ `CALL ..._div_{rn_noftz,rz,rd,ru}_f32(_slowpath)` |
| `div.f64`（无任何修饰符） | **拒绝**：`Rounding modifier required for instruction 'div'`（f64 没有 `.approx` 逃逸路径） |
| `div.approx.f64` / `div.full.f64` | **拒绝**：`Illegal modifier '.approx'` / `Unexpected instruction types specified for 'div.full'`——近似和全精度快速除法都是 f32-only |
| `div.{rn,rz,rm,rp}.f64` | B 类长序列，结构与 f32 同构（`MUFU.RCP64H` + `CALL` 到对应 slowpath） |

`FCHK` 只在 `div.rn`（f32）出现，是本族目前唯一一条"IEEE 合规性检查"专用指令，值得作为 `div` 套件的独立观测点。

### cvt（抽样 20 点，覆盖任务要求的 f32↔s32/u32、f64↔f32、f32↔f16/bf16、rni/rzi、sat、ftz）

| PTX | SASS | 备注 |
|---|---|---|
| `cvt.rzi.s32.f32` | `F2I.TRUNC.NTZ` | truncate-toward-zero |
| `cvt.rni.s32.f32` | `F2I.NTZ` | round-to-nearest-int 是"裸" `F2I`（无 `.TRUNC`），`.NTZ` 后缀恒定存在（与 rn/rz 选择无关，推测是"non-trapping"或 tie-break 标记，留 DESIGNED 精确定义） |
| `cvt.rni.u32.f32` | `F2I.U32.NTZ` | 无符号目的类型进 `.U32` 中缀 |
| `cvt.rzi.sat.s32.f32` | `F2I.TRUNC.NTZ`（与非 sat 版本文本相同） | `.sat` 不体现在 mnemonic 文本，需查编码位区分（留 DESIGNED） |
| `cvt.rzi.sat.ftz.s32.f32` | `F2I.FTZ.TRUNC.NTZ` | `.ftz` 单独进中缀，与 sat 位无关 |
| `cvt.s32.f32`（无 rounding） | **拒绝**：`Rounding modifier required for instruction 'cvt'` | float→int 转换的舍入修饰符不可省略 |
| `cvt.rn.f32.s32` | `I2FP.F32.S32` | int→float，`.rn` 不进后缀 |
| `cvt.f32.s32`（无 rounding） | **拒绝**：同上诊断 | int→float 同样不可省略舍入 |
| `cvt.rz.f32.s32` | `I2FP.F32.S32.RZ` | |
| `cvt.rn.f32.u32` | `I2FP.F32.U32` | 无符号源类型进中缀 |
| `cvt.f64.f32`（无 rounding，widening） | `F2F.F64.F32` | **widening 转换不接受舍入修饰符**：`cvt.rn.f64.f32` 被拒绝（`Illegal rounding modifier for instruction 'cvt'`）——已被推翻的假设"cvt 一律要求显式 rounding" |
| `cvt.rn.f32.f64`（narrowing） | `F2F.F32.F64` | narrowing 反过来**必须**显式 rounding（`cvt.f32.f64` 无 rounding 被拒绝：`Rounding modifier required`） |
| `cvt.rz.f32.f64` | `F2F.F32.F64.RZ` | |
| `cvt.rn.f16.f32`（narrowing） | `F2FP.F16.F32.PACK_AB` | 打包进 32 位寄存器一半，另一半 `RZ` |
| `cvt.rn.ftz.f16.f32` | `F2FP.F16.F32.PACK_AB`（与非 ftz 文本相同，ftz 效应在编码位） | |
| `cvt.rn.bf16.f32` | `F2FP.BF16.F32.PACK_AB` | 与 f16 同一指令家族，只换目的子类型 |
| `cvt.rn.f32.f16`（widening） | **拒绝**：`Illegal rounding modifier for instruction 'cvt'` | 与 f64/f32 widening 同一模式 |
| `cvt.f32.f16`（widening，无 rounding） | `HADD2.F32 Rd,-RZ,Ra.H0_H0` | **折叠类的第二个实例**：widening half→float 转换没有独立的 F2F/F2FP 反向路径，而是复用半精度打包加法单元算 `0 + a` 来完成类型扩展——已被推翻的假设"cvt 都走 F2F/F2FP/F2I/I2F 四个专用单元" |

cvt 空间远大于以上 20 点（还有 s64/u64、f16x2/bf16x2 打包形态、`.relu`、跨符号整数窄化等），本文按任务要求只做代表抽样，全矩阵留 `DESIGNED`。

## 审查缺口在本族的落实

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | 本族无异步/协议指令，不存在调度区域记分牌；退化为纯算术指令背靠背链的相邻指令控制字（stall/yield/reuse/barrier）差分。`fma` 套件的 `chain_depth_{2,4}`（依赖）与 `chain_parallel_2`（独立）expanded case 提供该差分所需的两种上下文；runtime 保留全函数 `full_instructions`（128-bit 编码），控制字复算不需要重跑 |
| P0-2 合法面未证伪 | 负向探针登记 `expected_diagnostic` 子串，`fma` 套件 10 条全部先探针取真实诊断再登记；上表"已校准合法面"记录 8 条被推翻的假设，其中 2 条（`fma.f16` 合法、修饰符顺序非规范化）作为 `fma` 套件的补集抽样探针/expanded case 落地 |

## 每指令研究重点

### `fma`（直译，套件已建，`FRAMEWORK_VALIDATED`）

1. 舍入修饰符强制显式——与 add/sub/mul 的"省略即 rn"形成对照，规则挖掘时不能把"省略"当成第五档舍入值处理，必须在语法层面就分叉。
2. `CALL`-based B 类序列（`rcp.rn`/`sqrt.rn`/`div.rn` 等）与 `fma` 的直译形成鲜明对比，说明"是否需要长序列"不是按指令族划分而是按"该运算在目标硬件上是否有原生全精度单元"划分：`fma` 有原生 `FFMA`/`DFMA`（IEEE 754 fusedMultiplyAdd 定义为单指令单舍入），`div`/`rcp`/`sqrt` 没有原生全精度除法/开方单元，只能靠 `MUFU` 近似 + 牛顿迭代 + 慢路径校正合成。
3. `guarded` case 的 if-conversion 现象需要与 `02_tma` 的"guard 落到 uniform predicate"结论并列写入跨族对比表：同一 PTX 语法元素（`@%p`）在不同副作用类别的消费者上有本质不同的编译策略。

### `add` / `sub` / `mul`（直译/折叠，`DESIGNED`）

1. `sub` 恒等于 `add` 取负——套件建设时 `target_patterns` 必须用 `FADD`/`DADD`（与 `add` 共享），不能指望有独立的 `SUB`/`FSUB` 助记符；`sub` 目录的套件应显式验证并在文档标注"本目录零 SASS 命中，与 add 共用一切正向证据，只对负操作数取负位做符号级断言"。
2. `mul` 与 `fma` 的 FMA contraction 交互（`a*b+c` 是否被自动合成 `fma`）留给 `mul`/`add` 建套件时用背靠背 `mul`+`add` 序列专项验证，`fma` 套件本身不覆盖这条（`fma` 套件的输入全部是显式 `fma` PTX，不测试契约合成）。
3. `add`/`mul` 是否也接受非规范修饰符顺序（`fma` 已证実），需要专项探针，暂列 DESIGNED。

### `div`（直译/序列/序列-B，`DESIGNED`）

1. `FCHK` 是本族目前唯一的"IEEE 合规检查"专用指令，仅在 `div.rn.f32` 出现（`rz`/`rm`/`rp` 变体不用它，直接进慢路径 `CALL`）——需要研究其操作数语义（谓词输出用途）和它是否在其他 rn 形态（`rcp.rn`/`sqrt.rn`）里也隐藏出现（初步探针未见，需要专项确认）。
2. approx/full/rn 三档 × f32/f64 × 四种舍入，是本族修饰符空间最大的单一指令，建套件时序列长度差异巨大（2 条到 144 条），`empty_target_allowed`/长度容忍度需要单独设计。
3. `CALL`/`RET` 子程序体在多少个 case 间共享（同一 kernel 内多次调用 `div.rn.f32` 是否复用同一份 slowpath 还是各生成一份）留待建套件时用 `chain_depth` 式的重复调用 case 验证——这直接决定"B 类序列证据是否可裁剪成单份记录"还是"每个调用点都要单独记录"。

### `min` / `max`（直译 f32 / 序列 f64，`DESIGNED`）

1. f32 与 f64 结构不同源（`FMNMX` 单指令 vs `DSETP+SEL+FSEL+LOP3` 四指令序列），套件必须分别建轴，不能假设同一 `target_patterns` 能同时捕获两者（f64 需要额外把 `DSETP.MIN`/`DSETP.MAX` 也纳入 target_patterns 或改用序列签名匹配）。
2. `.xorsign`/`.abs` 互相强制的语法约束是很好的负向探针素材（两个方向各一条）。
3. f64 序列里 `@P1 LOP3.LUT` 只在 `P1`（`DSETP` 的第二个谓词输出，推测标记 unordered/NaN 情形）为真时执行——这是研究 f64 min/max 如何处理 NaN payload 传播的入口，纯静态编译不能验证其数值语义，需要在文档里明确标注为 `STATIC_ONLY` 边界外的问题，只记录"存在该修正分支"这一结构事实。

### `abs` / `neg`（折叠，`DESIGNED`，无独立套件计划）

1. 两者都没有独立 SASS opcode，不满足"至少一个旗舰 opcode 套件"的旗舰候选资格（会持续产生 `TARGET_ELIMINATED` 或需要人工判定"折叠是否发生"而非简单子串匹配）；已并入 `fma` 套件的 `fold_*` expanded 轴作为主要证据来源，后续如果需要独立文档化，应以"消费者矩阵"（abs/neg 分别喂给 add/mul/fma/min/max）为主轴而不是自身的修饰符矩阵。
2. 无消费者时退化为 `FADD |x|,-RZ` / `DADD -RZ,-Ra` 的具体触发条件（是否只在直接喂 `st` 时发生，还是任何"名义消费者"都会触发）需要更多探针，暂列 DESIGNED。

### `rcp` / `sqrt` / `rsqrt` / `lg2` / `ex2.f32-f64` / `sin` / `cos`（MUFU/序列/序列-B，`DESIGNED`）

1. 七个指令共享 `MUFU.*` 家族但合法面互不相同（见结构分类总表），套件路线图必须逐指令单独建，不能复用同一 `suite_spec.py` 模板里的合法矩阵假设。
2. B 类长序列的 `CALL`/`RET` 子程序符号名（`$__internal_0_$__cuda_sm20_*`/`$__internal_0_$__cuda_sm3x_*`）自身携带架构代号（`sm20`/`sm3x`），说明这批慢路径是跨代复用的遗留库代码而非 Thor 专门生成——这是"运行时库依赖"层面的证据，超出 `STATIC_ONLY` 的指令选择范畴，但值得在 `P1-4`（ELF/cubin 装配层缺口，见 `01_tcgen05` 审查）关联记录：这些符号在最终 cubin 里如何解析/是否内联到每个调用点，属于装配层问题。
3. `ex2.f32-f64` 目录名暗示支持 f64，但实测 `ex2.approx.f64` 被拒绝——需要在该目录 README 里显式澄清"目录名沿用 PTX 手册的家族命名惯例，不代表 f64 分支已验证存在"。
4. `sin`/`cos` 的参数归约乘数 `0.15915493667125701904`（即 `1/(2π)`）应作为规则挖掘的一个断言点：只要出现 `MUFU.SIN`/`MUFU.COS`，前一条必然是以该常量为乘数的 `FMUL.RZ`，这是比"只匹配 MUFU 助记符"更强的归属证据，套件设计时应考虑把这一对指令当作一个不可拆分的 target_pattern 组合。

### `cvt`（直译为主 + 折叠个案，`DESIGNED`）

1. 20 点抽样已覆盖任务要求的全部类别；`.sat` 在 `F2I` 家族的 mnemonic 文本层面不可见（需查编码位区分 sat/非 sat），这是 cvt 套件设计时归属逻辑必须处理的特殊情况——不能只靠字符串匹配助记符判断 sat 是否生效。
2. `cvt.f32.f16` 折叠进 `HADD2.F32` 是本族第二个"折叠到无关功能单元"的实例（第一个是 `sub`→`add`），提示宽化转换在这颗芯片上系统性地借道最近的通用算术单元而非专用转换单元；建议在扩大 cvt 抽样时专门验证 `cvt.f32.bf16`（宽化）是否走同一路径。
3. 全矩阵（s64/u64、压缩打包类型、`.relu`）留 `DESIGNED`，按 P0-2 要求，扩大抽样时必须继续用"先探针后登记"流程，不能从这 20 点外推。

## `STATIC_ONLY` 边界声明

全部结论为 `STATIC_ONLY`：编译通过、反汇编成功、目标指令归属成功，都只证明"ptxas 选择了这些 SASS 指令/序列结构"，不证明任何数值结果的正确性。本族的边界声明比协议类指令族（`01_tcgen05`/`02_tma`）多一层，因为浮点语义天然引入"结果集合"而非"单一预期值"：

- **数值 oracle 不在本族范围内**：任何 case 的运行时输出是否 bit-exact、是否落在 IEEE 754 规定的舍入结果内，都不属于本套件的通过条件。但设计约束仍然存在——按指令语义把"允许结果集合"分类记入设计文档，供未来运行时验证阶段直接取用，是本族独有的 P2 附加要求：
  - `.rn`/`.rz`/`.rm`/`.rp` 全精度形态（`fma` 全部、`rcp.rn`/`sqrt.rn`/`div.rn` 等）：oracle 应为 **bit-exact**（IEEE 754 定义单一正确舍入结果）。
  - `.approx` 近似形态（`MUFU.*` 直接产物及其短序列包装）：oracle 应为**误差界**（PTX ISA 对每个 approx 指令规定了相对误差上限，例如 `rcp.approx.f32` 与精确值的相对误差 ≤ 2⁻²²等），不能要求 bit-exact。
  - `min`/`max` 涉及 NaN 操作数时：oracle 应为**允许结果集合**（IEEE 754-2019 对 NaN 传播和 payload 选择留有实现自由度，`.NaN` 修饰符改变的是"遇到 NaN 时返回 NaN 还是返回数值"这一策略而非唯一定值）。
  - `cvt` 到整数类型且发生溢出/`.sat`：oracle 应为**饱和边界值**（钳制到目标类型可表示范围的端点），非饱和且溢出时是**未定义行为**（不应断言具体返回值）。
- **子程序符号解析**：B 类长序列里的 `$__internal_..._slowpath` 符号在最终可加载 cubin 中如何重定位/是否跨 kernel 共享同一份代码，属于 `01_tcgen05` 审查 P1-4（ELF/cubin 装配层）的范畴，本文档只记录符号名和调用点结构，不做装配层验证。
- **跨版本/跨架构**：全部结论只在本机 CUDA 13.0（ptxas V13.0.88 / nvdisasm V13.0.85）、`sm_110a` 上验证过；`fma` 套件已支持 `--ptxas`/`--nvdisasm` 参数化，跨版本重跑不需要改代码，但尚无第二组工具链的差分证据。
