# TMA 族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。文中"实测"来自本机 74 个校准探针的 O0/O3 编译反汇编，以及已建成的两个套件（`cp.async` 45 case、`cp.async.bulk.tensor` 94 case）的 O0–O3 全量自检；校准探针脚本在会话 scratchpad，套件可重现全部结论。
> 设计基线：`01_tcgen05` 的静态实验分层（syntax/expanded/negative/O0–O3/归属/规则挖掘），并逐条吸收 `01_tcgen05/对抗式审查_实验设计缺口.md` 的 P0/P1 结论。

## 结论

TMA 族 11 个 opcode 全部落在 tcgen05 分类法的 A 类和 C 类，**没有 B 类（编译器合成协议）也没有 D 类（零指令调度约束）**：每条 PTX 指令都产生 1–2 条可归属的 SASS。因此 tcgen05.ld 式的"单指令直译"框架对全族适用，不需要 alloc 那样的序列模板研究。但对抗式审查的 P0-1（控制位是全局资源）对本族同样成立——TMA 的正确性协议恰恰全部走 scoreboard（`DEPBAR.LE SB0`）与 mbarrier，所以每个套件从第一天起就内置在飞深度、消费距离和模板变量三个上下文轴。

| 类别 | 指令 | PTX→SASS 结构 |
|---|---|---|
| A 单指令直译 | `cp.async`、`cp.async.bulk`、`cp.reduce.async.bulk`、`cp.async.bulk.prefetch`、`cp.async.bulk.tensor`、`cp.reduce.async.bulk.tensor`、`cp.async.bulk.prefetch.tensor` | 1 条 PTX → 1 条 SASS，qualifier 逐个对应 modifier，cache_hint 例外（改操作数形态） |
| C 完成节点 | `cp.async.commit_group`、`cp.async.bulk.commit_group` | 1 条 PTX → 1 条 SASS（`LDGDEPBAR` / `UTMACMDFLUSH`），无操作数，语义完全由上下文决定 |
| C 完成节点（1→1~2） | `cp.async.wait_group`、`cp.async.bulk.wait_group` | `DEPBAR.LE SB0, N`；bulk 侧非 `.read` 形态额外产生 `CCTL.IVALL` |

## 实测助记符总表

### tensor 族（`UTMA*`）

| PTX | SASS |
|---|---|
| `cp.async.bulk.tensor.{1..5}d...tile.mbarrier::complete_tx::bytes`（load） | `UTMALDG.{1D..5D}` |
| `.tile::gather4`（仅 2d） | `UTMALDG.2D.GATHER4` |
| `.im2col`（3d–5d，offsets 为 `.b16`） | `UTMALDG.{3D..5D}.IM2COL`，offsets 打包成额外 UR 操作数 |
| `.im2col::w` / `.im2col::w::128`（3d–5d） | `.W` / `.W128` |
| `.multicast::cluster`（仅 cluster dst，mask 为 `.b16`） | `.MULTICAST` + mask UR 操作数 |
| `.cta_group::1` / `::2` | 无后缀 / `.2CTA`（两种拼写位置均被接受） |
| `.L2::cache_hint` | 不进助记符，追加 `desc[UR]` 操作数 |
| `dst = shared::cta` 与 `shared::cluster` | 助记符与修饰符完全相同（同 tcgen05.commit 的 state-space 不进助记符） |
| store `.tile` / `.tile::scatter4` / `.im2col_no_offs`（`.bulk_group`） | `UTMASTG.{1D..5D}` / `.SCATTER4` / `.IM2COL` |
| `cp.reduce.async.bulk.tensor ... .{add,min,max,dec,...}` | `UTMAREDG.{rank}.{ADD,MIN,MAX,DEC}`——**无类型后缀**，元素类型由 tensormap 运行时决定 |
| `cp.async.bulk.prefetch.tensor ... .tile/.im2col/.tile::gather4` | `UTMAPF.L2.{rank}{.IM2COL,.GATHER4}` |
| guard 谓词 `@%p` | 落到 uniform predicate：`@!UP1 UTMALDG.2D ...` |

### 非 tensor bulk 族（`UBLK*`）

| PTX | SASS |
|---|---|
| `cp.async.bulk.shared::{cta,cluster}.global`（mbarrier 完成） | `UBLKCP.S.G`（cta/cluster 同形） |
| `... .multicast::cluster` | `UBLKCP.S.G.MULTICAST` |
| `cp.async.bulk.global.shared::cta.bulk_group` | `UBLKCP.G.S` |
| `cp.async.bulk.shared::cluster.shared::cta`（DSMEM） | `UBLKCP.S.S` |
| `cp.async.bulk.prefetch.L2.global` | `UBLKPF.L2` |
| `cp.reduce.async.bulk...add.u32` / `.and.b32` | `UBLKRED.G.S.ADD` / `.AND`（无类型后缀） |
| `...min.s32` | `UBLKRED.G.S.MIN.S32`（符号性才进后缀） |
| `...add.f32` / `.add.noftz.f16` | `UBLKRED.G.S.ADD.F32.RN` / `.ADD.F16.RN`（出现舍入模式） |

### classic 族（`LDGSTS`）

| PTX | SASS |
|---|---|
| `cp.async.ca.shared.global, {4,8,16}` | `LDGSTS.E` / `.E.64` / `.E.128` |
| `cp.async.cg.shared.global, 16` | `LDGSTS.E.BYPASS.128` |
| src-size（zero-fill） | `.ZFILL`，且源地址出现 `+ (cp-size − src-size)` 偏移（机制待归属） |
| src-size = 0 | 折叠为 ignore-src 操作数形态 `, !PT` |
| ignore-src 谓词 | 追加谓词操作数（可折叠时为字面 `!PT`） |
| `.L2::{64,128,256}B` | `.LTC64B` / `.LTC128B` / `.LTC256B` |
| `.L2::cache_hint` | 不进助记符：dst 从 `[R]` 迁到 `[UR]`，descriptor 变为 `desc[UR]`（操作数形态变化，待深入） |
| `shared` 与 `shared::cta` 拼写 | 同一 SASS |

### 完成协议

| PTX | SASS |
|---|---|
| `cp.async.commit_group` | `LDGDEPBAR` |
| `cp.async.wait_group N` | `DEPBAR.LE SB0, N`（N 直接进立即数，双 group 实测 `0x1`） |
| `cp.async.wait_all` | `LDGDEPBAR` + `DEPBAR.LE SB0, 0x0`（无显式 commit 也成对出现） |
| `cp.async.bulk.commit_group` | `UTMACMDFLUSH` |
| `cp.async.bulk.wait_group N` | `DEPBAR.LE SB0, N` + `CCTL.IVALL` |
| `cp.async.bulk.wait_group.read N` | `DEPBAR.LE SB0, N`（**无** `CCTL.IVALL`——`.read` 与完整 wait 的差异就是一条缓存失效） |

## 合法面实测（已进套件负向探针的部分）

| 探针 | 诊断 |
|---|---|
| tensor rank 6d | 语法层拒绝（parse error） |
| tensor load 缺完成机制 | `.completion_mechanism modifier required` |
| 坐标数 ≠ rank | `Argument vector size mismatch`（与通用 `Arguments mismatch` 是不同检查器） |
| im2col offsets 用 `.b32` | `Arguments mismatch` |
| store 用 mbarrier 完成 | `Arguments mismatch` |
| gather4 非 2d / im2col 2d | `Modifier ... cannot be combined` |
| scatter4 用于 load 方向 | `Illegal modifier` |
| multicast + `shared::cta` dst | `Illegal modifier '.multicast::cluster' ... with '.shared::cta.global'` |
| classic size ∉ {4,8,16}、`cg` size ≠ 16、size 为寄存器、src-size > cp-size、src-size 与 ignore-src 并用、`shared::cluster` dst | 各自独立诊断（见 `cp.async/thor_ptx90/suite_spec.py`） |
| bulk s2g 配 mbarrier、s2s 目的为 cta、bulk size 立即数非 16 倍数 | 各自独立诊断（待建 `cp.async.bulk` 套件时登记） |

一个被校准推翻的假设：`tile::gather4` 的 prefetch 形态是合法的（`UTMAPF.L2.2D.GATHER4`）。这说明按规范阅读划定合法面确实会犯错（P0-2 的论点），所以本族所有套件的负向探针都必须携带 `expected_diagnostic` 子串，且保留"预期非法却编译通过"作为发现渠道。

## 对抗式审查缺口在本族的落实

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | 每个套件的 expanded 内置 `inflight_depth`（2/4 条在飞）、`wait_distance`、`group_depth` 轴；runtime 保留全函数指令的 128-bit 编码（`full_instructions`），控制字差分不需要重跑实验 |
| P0-2 合法面未证伪 | 负向探针登记 `expected_diagnostic` 子串，拒绝必须定位到声称的约束；每套件含假定合法面之外的补集抽样探针 |
| P0-3 组合/序列不足 | wait/commit 族的语义只在序列上下文中存在，其套件设计以"深度 × 距离 × 类型混合"为主轴而非孤立指令；classic 与 bulk 两条流水线是否共享 SB0 记分牌列为首要序列问题 |
| P1-1 模板未受控 | 每套件 expanded 含 `template_wide`（加宽/打乱参数签名）case |
| P1-2 重物化前提 | tensormap/坐标/mbar 地址各有 indirect producer case（不可折叠来源） |
| P2-1 单版本 | 套件与 tcgen05 相同接受 `--ptxas/--nvdisasm` 路径参数，跨版本差分只需换工具链重跑 |

## 各指令研究重点

### `cp.async`（A，套件已建，`FRAMEWORK_VALIDATED`）

1. `.ZFILL` 的源地址偏移 `+ (cp-size − src-size)` 是编码技巧还是寻址语义，需要归属到操作数编码层。
2. `.L2::cache_hint` 引起的 dst `[R]→[UR]` 迁移：确认这是 cache-policy descriptor 的固定 lowering 还是寄存器分配巧合（用多变量上下文重测）。
3. guard 谓词在 O3 下从 `LDGSTS` 上消失（疑似转成分支或被均匀化），需要用非均匀谓词重测。
4. O3 下 `LDGSTS` 前出现三条 `@!PT LDS RZ`（仅 classic 探针可见），归属未知，列为待查调度习语。

### `cp.async.commit_group` / `cp.async.wait_group`（C）

1. 1:1 映射已确认（`LDGDEPBAR` / `DEPBAR.LE SB0, N`），研究单元必须是序列：commit 前在飞条数 0/1/2、`wait_group N` 的 N 与实际 group 数的所有组合、`wait_all` 的成对 lowering。
2. 关键问题：`DEPBAR` 用的 SB0 与其他 scoreboard 消费者（bulk wait、`tcgen05` LDTM 等）是否同一资源池——直接决定"贴模板"能否跨族拼接。
3. 空等待（无在飞操作时 `wait_group 0`）是否被消除，对应 tcgen05 审查里"等待被消除"的风险面。

### `cp.async.bulk`（A）

轴：方向三态（S.G / G.S / S.S）× dst cta/cluster（已证同形）× multicast × cache_hint × size 来源（立即数/寄存器）。负向面已校准三条（见上表）。独有问题：size 为寄存器时 16 对齐检查移到何处（静态消失，应记 `TARGET_UNSUPPORTED`→运行时验证边界）。

### `cp.reduce.async.bulk`（A）

轴：op（add/min/max/and/or/xor/inc/dec）× 类型（u32/s32/u64/f32/f16/bf16…）。已证后缀规则非平凡：无符号整型 op 不带类型后缀、有符号才带 `.S32`、浮点带 `.F32.RN`。规则必须按"op×type → 后缀"组合登记，不能拆两条轴（同 tcgen05.cp 的 shape×multicast 融合教训）。`noftz` 是否进编码待查。

### `cp.async.bulk.prefetch`（A）

`UBLKPF.L2`。轴少：size 来源 × cache_hint。可与 `cp.async.bulk` 共日程。

### `cp.async.bulk.tensor`（A，套件已建，`FRAMEWORK_VALIDATED`）

1. 操作数打包：`UTMALDG [URa], [URb]` 中坐标+tensormap 打包进连续 UR 向量，UR 个数随 rank/模式变化——需要 allocation 层观测（复用 `00_shared/tools/normalize_sass.py` 的寄存器类别规范化）确认打包布局是否随 rank 稳定。
2. `cta_group` 两种拼写位置（`.tile.cta_group::2.mbarrier...` 与 `...bytes.cta_group::2`）同 SASS，已进 expanded 拼写变体 case；逆向规则必须把两种拼写归入同一 semantic form。
3. dst cta/cluster 同形 ⇒ 差异只可能在操作数编码或运行时地址翻译；与 `15_cluster_dsmem` 的 `mapa` 交叉验证后才能下"无差异"结论。
4. `.2CTA`、`.MULTICAST` 与 mbarrier 完成的组合已验证可静态编译，跨 CTA 语义验证依赖 `03_mbarrier` 与 `15_cluster_dsmem` 的结论，本目录不重复建账。

### `cp.reduce.async.bulk.tensor`（A）

`UTMAREDG.{rank}.{OP}` 无类型后缀（类型在 tensormap 里）——与非 tensor 的 `UBLKRED` 形成鲜明对照，是"descriptor 不透明性"再次成立的证据。轴：op × rank × tile/im2col_no_offs × cache_hint。注意 `.dec` 合法且映射 `.DEC`。

### `cp.async.bulk.prefetch.tensor`（A）

`UTMAPF.L2.{rank}{.IM2COL,.GATHER4}`，无目的操作数、无完成机制。轴：rank × 模式 × cache_hint。gather4 合法性已实测（规范阅读易漏）。

### `cp.async.bulk.commit_group` / `cp.async.bulk.wait_group`（C）

1. `UTMACMDFLUSH` 无操作数，`commit` 的语义全部在"它 commit 了哪些在飞操作"——套件主轴是前序操作类型混合（UBLKCP / UTMASTG / UTMAREDG 同时在飞）与深度。
2. `.read` 与完整 wait 的差异是一条 `CCTL.IVALL`：这是"漏一条指令 = 静默内存一致性错误"的典型（对应 tcgen05 审查对 fence 类的警告），生成器必须把 `CCTL.IVALL` 视为 `wait_group`（非 read）lowering 的必要组成部分，不能当可选外围。
3. `DEPBAR.LE SB0, N` 的 N 已证与 PTX 立即数一致（0/1 实测），需补 N > 在飞 group 数、N=63 边界等 case。

## 边界声明

全部结论为 `STATIC_ONLY`：编译通过 + 归属成功不证明数据搬运、mbarrier 到达、transaction bytes 记账或 `CCTL.IVALL` 的可见性语义。tensormap 内容视为不透明（同 tcgen05 descriptor 的裁决）：套件用不透明 `.u64` 参数指针即可让 ptxas 完成全部 lowering，编译器不读 tensormap 内部字段。mbarrier 的 `SYNCS.EXCH.64` lowering 出现在所有 load case 的 PREPARATION 区，其规则由 `03_mbarrier` 持有，本族不重复登记。
