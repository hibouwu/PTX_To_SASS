# 08 控制流族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。文中"实测"来自本机 38 个 scratchpad 校准探针的 O0/O3 编译反汇编，以及旗舰套件 `brx.idx/thor_ptx90/`（18 syntax + 25 expanded case，O0–O3 共 172 次编译、反汇编与归属，7 个带诊断锚定的负向探针）的全量自检。校准探针脚本未入库（scratchpad 会话临时文件），套件本身可重现旗舰 opcode 的全部结论；`bra`/`call`/`ret`/`exit` 四个非旗舰 opcode 的结论以本文引用的探针源码摘录为证据，尚待补建套件复现。
> 设计基线：`01_tcgen05`/`02_tma` 的静态实验分层（syntax/expanded/negative/O0–O3/归属/规则挖掘），并逐条吸收 `01_tcgen05/对抗式审查_实验设计缺口.md` 的 P0/P1 结论与本族门槛（"必须区分 PTX 源布局、优化后 CFG 和最终 SASS 布局"）。

## 结论

`08_control_flow` 与 `02_tma` 的结构性差异很大：TMA 11 个 opcode 全部落在"1 条 PTX → 1–2 条可归属 SASS"的直译框架内，控制流不是。**同一条 PTX 控制流指令，其 SASS 形态由所在调度区域的编译器决策决定，而不是由指令本身的语法决定**——同一条 `@%p bra L1;`，视谓词的 warp-uniform 性和目标块是否可谓词化，可以分别 lower 成"整体消失（if-conversion）""朴素 `@P BRA`""`BSSY.RECONVERGENT`/`BSYNC.RECONVERGENT` 包裹的 `@P BRA`"三种互不相同的 SASS 形态，指令数从 0 到 N+2 不等。这正面回应了 tcgen05 审查 P0-3（"编译器决策单元是区域，不是指令"）在本族的具体形式：**本族的"决策单元是区域"不是抽象原则，而是可以直接从 SASS 数出指令条数的实测事实**。

第二个结构性事实是**过匹配**：本族全部 5 个 opcode 的助记符（`BRA`/`BRX`/`CALL`/`RET`/`EXIT`）与 kernel 尾部恒定出现的收尾结构重叠——每个 kernel 不论内容如何，结尾恒为 `EXIT` 后跟一个自跳 `.L_x_N: BRA \`(.L_x_N)` 陷阱块（`probe:baseline`，O0–O3 一致）。`target_patterns` 若用 `"BRA"` 或 `"EXIT"` 子串匹配，基线（不含任何目标指令的脚手架 kernel）必命中，归属从第一天起就是污染的。这是选择 `brx.idx` 作为旗舰的直接原因：`BRX`/`BRXU` 是本族唯一从不出现在收尾结构里的助记符，可以用干净的子串匹配验证；`bra`/`call`/`ret`/`exit` 四个非旗舰 opcode 的套件建设必须先解决"逐指令归属需要块结构而非子串匹配"的方法论问题，本文把这一点列为独立小节（见下）。

## 结构分类

本族不适合套用 tcgen05 的 A/B/C/D 直译分类（该分类假设"给定语法形态，SASS 形态唯一"），因为控制流的核心事实恰恰是这一假设不成立。改用按"决策稳定性"分类：

| 类别 | 指令 | 决策稳定性 |
|---|---|---|
| 稳定终止 | `exit`（含谓词）、entry 级 `ret` | 恒定 1 条 PTX → 1 条 `EXIT`（谓词化时为 `@P EXIT`），不受区域上下文影响，是本族唯一"稳定直译"的子集 |
| 稳定配对、不稳定内部 | `call`、`.func` 级 `ret` | `CALL.REL.NOINC`/`RET.REL.NODEC` 配对恒定出现（ptxas 从不内联），但 `.func` 内提前 `ret` 会被整体控制流重构（复制尾部 + 跳转），不是"该 PTX 指令" 1:1 对应"该 SASS 指令" |
| 区域决定型 | `bra`（谓词/无条件）、`brx.idx` | SASS 形态（0 条 / 朴素分支 / 重汇聚包裹分支 / 多路索引跳转）由整个调度区域的 uniform 性分析和可谓词化性共同决定，同一条 PTX 指令在不同上下文可以产生完全不同的指令数和助记符集合 |

## 过匹配与归属方法论（本族对 P0-3 的正面回应）

**实测（`probe:baseline`）**：任意 kernel，无论 body 内容，O0–O3 反汇编尾部恒为：

```
        /*xxxx*/    EXIT ;
.L_x_N:
        /*xxxx*/    BRA `(.L_x_N);
        /*xxxx*/    NOP;
        ... (NOP 补齐到对齐边界)
```

这意味着：
1. `target_patterns=("EXIT",)` 或 `("BRA",)` 对本族任何指令的套件都不可用——基线零命中检查（[建族套件指南.md](../00_shared/templates/建族套件指南.md) 强制要求）必然失败。
2. `brx.idx` 的 `BRX`/`BRXU` 是本族里唯一不参与这一收尾结构、可安全用作 `target_patterns` 的助记符，这是选择它为旗舰的直接依据（已用 18+25 case 的旗舰套件实测确认零污染，见 [`brx.idx/thor_ptx90/README.md`](brx.idx/thor_ptx90/README.md)）。
3. `bra`/`call`/`ret`/`exit` 的套件（未来路线图，见文末）不能用子串匹配做归属，必须做**块结构归属**：以 PTX 源里的标号/label 为锚点，在 SASS 里定位对应的基本块边界（`.L_x_k:` 标号 + 该块内的指令序列），再统计块内而非全函数的目标助记符出现次数。落到实现上，意味着这四个 opcode 的 `suite_runtime.py` 归属逻辑不能照抄 TMA 的"全函数子串扫描"，需要扩展为"按 `.L_x_k:` 分块后再扫描"，或者改用"目标块内立即数/store 偏移作为锚点，反查该块内第一条匹配助记符"的间接归属法。这是本族相对 TMA/tcgen05 框架的一个真实扩展点，不是"以后再说"的空话——本文在此登记为路线图任务，而非在 `brx.idx` 套件里假装解决了它（`brx.idx` 能用子串匹配是因为它足够幸运，不是因为方法论已经推广）。

## 实测助记符总表

### `exit`

| PTX | SASS | 备注 |
|---|---|---|
| `exit;`（无条件） | `EXIT` | 与 entry 级 `ret;` lowering 等价 |
| `@%p exit;`（divergent 谓词，如 `%tid.x` 派生） | `@P0 EXIT` | **直接谓词化**，不经过 skip-branch 重构，也不套 `BSSY`/`BSYNC`（`probe:exit_predicated`，O0 与 O3 一致） |

`exit` 是本族唯一"退出的 lane 永不汇合"的指令，因此编译器不需要重汇聚栈簿记——这与 `bra`/`call`/`brx.idx`（都需要在分支之后汇合）形成结构性对照，是理解本族重汇聚机制适用范围的关键锚点。

### entry 级 `ret` / `.func` 级 `ret`

| PTX 位置 | SASS | 备注 |
|---|---|---|
| `.visible .entry` 内的 `ret;` | `EXIT` | 与 `exit;` 等价；`RET` 类助记符从不出现在 entry 函数里 |
| `.func` 内的尾部 `ret;` | `RET.REL.NODEC Rn \`(caller_label)` | `Rn` 是 `CALL.REL.NOINC` 在调用点写入的返回地址寄存器 |
| `.func` 内**提前**（谓词化）`ret;`（`@%p ret;` 后面还有代码） | **不是** `@P RET`；重构为 `@!P BRA` 跳过剩余函数体，两个出口各自携带一份 `RET.REL.NODEC`（`probe:ret_predicated`，O0） | 没有观察到任何"谓词化 RET"的 SASS 形态；ptxas 恒定选择"复制尾部 + 无条件跳过"而不是"谓词化终止指令" |

### `call`

| PTX | SASS | 备注 |
|---|---|---|
| `call.uni (%r), f, (...)` / `call (%r), f, (...)`（无 `.uni`） | 两者产生字节相同的 `CALL.REL.NOINC \`($caller$f)`（`probe:call_nonuni` vs `probe:call_basic`） | 本次探针未观测到 `.uni` 后缀对 lowering 的可见影响 |
| `@%p call.uni (...)`，`%p` divergent | `BSSY.RECONVERGENT`/`BSYNC.RECONVERGENT` 包裹 `@!P BRA` 跳过 + `CALL.REL.NOINC`（`probe:call_guarded_divergent`，O0 与 O3 一致） | 真实函数调用不可能被 if-conversion 消除（不像简单直线 `bra` body），因此 divergent 谓词下的 call **恒定**触发重汇聚包裹，O3 也不例外 |
| 任意 `.func` 调用，含仅单条指令的 trivial body | ptxas **从不内联**：O0–O3、任意函数体大小，均保留独立的 `CALL.REL.NOINC` + `RET.REL.NODEC` 配对（`probe:call_trivial`） | 见下方"意外发现" |
| `.func .noinline (...)` / `.noinline .func (...)` | **语法错误**（"Parsing error near '.noinline': syntax error"），两个位置均被拒绝（`probe:call_noinline`、`probe:call_noinline2`） | PTX 9.0 在本工具链上没有函数级内联控制指令；见下方"意外发现" |

### `bra`

| PTX | SASS | 备注 |
|---|---|---|
| `@%p bra L1;`，`%p` 从 `%tid.x` 派生（divergent），body 为直线代码，O0 | `BSSY.RECONVERGENT B0, ...` → `@P0 BRA` → （另一分支） → `BSYNC.RECONVERGENT B0` | 经典重汇聚栈模式，两分支各自落地后在 `BSYNC` 处汇合（`probe:bra_divergent`） |
| 同上，O3，body 足够小（无循环/调用） | **完全消失**：整个 if/else 被 if-conversion 成纯谓词化直线代码（`@P0 MOV`/`@!P0 IMAD.MOV`/`@P0 STG`/`@!P0 STG`），无 `BRA`、无 `BSSY`/`BSYNC` | 编译器优化掉了分支本身，不是优化掉了重汇聚簿记；见下方"P0-1 对应物"专节 |
| 同上，但 body 含循环（不可谓词化） | O3 下 `BSSY.RECONVERGENT`/`BSYNC.RECONVERGENT` **重新出现**，且嵌套（外层 if/else 一层，内层循环展开体又各自一层） | 证明 O3 是否消除重汇聚簿记完全取决于是否发生 if-conversion，与优化级别本身无关（`probe:bra_divergent_loop`） |
| `@%p bra L1;`，`%p` 从 kernel 参数（uniform）派生，O0 | 朴素 `@P0 BRA`，**无 `BSSY`/`BSYNC`** | uniform 值分析本身就足以证明该分支不可能导致 warp 内实际分叉，编译器据此跳过重汇聚簿记，即便语法上这仍是一条"谓词化条件分支"（`probe:bra_uniform`） |
| `@%p bra.uni L1;`，`%p` 仍是 divergent（tid 派生） | `.uni` 后缀**未能**抑制 `BSSY`/`BSYNC`：与不带 `.uni` 的形态完全一致 | 编译器不盲信 `.uni` 提示，仍按自己的一致性分析决策（`probe:bra_pred_uni_hint`） |

### `brx.idx`（旗舰，套件已建）

见 [`brx.idx/thor_ptx90/README.md`](brx.idx/thor_ptx90/README.md) 的"已校准的合法面 → SASS 现象对照"表；核心结论：O0 恒为 `BRX`（GPR），O1–O3 视索引是否 warp-uniform 切换 `BRX`/`BRXU`；`@%p brx.idx` 合法且遵循与 `bra`/`call` 相同的重汇聚规则。

## 本族 P0-1 对应物：divergence 处理与汇合点机制实测

tcgen05 审查的 P0-1 是"调度控制字段没有生成规则，只有编码簿"；TMA 把它对应到"在飞异步操作条数/消费距离"控制位轴。本族的直接对应物是**分支 divergence 的重汇聚控制位**——`sm_110a` 是否还保留 Volta 系公开资料描述的显式重汇聚栈指令？

**实测结论：保留，机制未变，但触发条件比语法层面复杂得多。**

1. `sm_110a` 上 divergent 分支**仍然**使用 `BSSY.RECONVERGENT`/`BSYNC.RECONVERGENT` 这一对显式重汇聚栈指令（`B0`/`B1` 等桶寄存器编号），语法与历史架构一致，不是转用了别的机制。
2. 是否出现这对指令，不取决于 PTX 语法层面"是否谓词化"或"是否带 `.uni`"，而取决于两件事的合取：
   - **谓词是否 warp-uniform**（由 ptxas 的值一致性分析判定，不是由 `.uni` 后缀声明）——uniform 谓词下无论 `bra`/`brx.idx` 的 guard 都不触发重汇聚；
   - **分支体是否可 if-conversion**——纯直线代码（无循环、无调用）在 O3 下会被谓词化掉，分支和重汇聚簿记一起消失；一旦分支体含循环或 `call`（真实控制转移，不可谓词化），重汇聚簿记在任何优化级别都会出现。
3. `brx.idx` 参与**同一套**机制：`@%p brx.idx` 在 guard 谓词 divergent 时同样触发 `BSSY.RECONVERGENT`/`BSYNC.RECONVERGENT`；旗舰套件的 `guard_divergent` case 额外观测到一层嵌套的 `BSSY.RELIABLE`/`BSYNC.RELIABLE`（`B1`），即 guard 的 skip-branch 用 `RECONVERGENT` 桶，`BRX` 自身的多路目标汇合另用一个 `RELIABLE` 桶——这是一个**未预期的实测发现**（见下）。
4. `exit` 不参与这套机制（见上表）——退出的 lane 不会再汇合，没有重汇聚点，这是它与 `bra`/`call`/`brx.idx` 的根本区别，而不是"资源用得少所以被优化掉"。

## 已校准合法面

| 探针 | 结果/诊断 |
|---|---|
| `brx.idx` 索引类型 `.b64` / `.f32` | 拒绝，`Arguments mismatch for instruction 'brx.idx'`（两种错误类型文本相同，是同一个"操作数形状检查"而非逐类型检查） |
| `brx.idx` 第二操作数为裸标号（未声明 `.branchtargets`） | 拒绝，同样是 `Arguments mismatch for instruction 'brx.idx'` |
| `brx.idx` 第二操作数引用完全未声明的符号 | 拒绝，同时产生 `Arguments mismatch` 与 `Unknown symbol '<name>'` 两条诊断 |
| `.branchtargets` 引用本函数内未定义的标号 | 拒绝，`Unknown symbol '<name>'` |
| `.branchtargets` 引用**另一个 `.func` 里真实存在**的标号 | 拒绝，诊断文本与"未定义"完全相同（`Unknown symbol '<name>'`）——标号作用域是函数局部的，跨函数引用在诊断层面和不存在没有区别 |
| `.branchtargets` 为空列表（`ts: .branchtargets;`） | 拒绝，`Parsing error near ';': syntax error`（语法层面，不是语义层面） |
| `brx.idx` 索引越界（编译期常量，超出 `.branchtargets` 长度） | **接受，零静态诊断**——`ptxas` 不对索引做静态边界检查，即使索引是字面常量；O0 产生真实 `BRX`（运行时行为未检查/未定义），O3 在 UB 假设下整体优化为裸 `EXIT` |
| `.branchtargets` 重复引用同一物理块（`L0, L0`） | **接受**（一个发现，非预期合法面之外的补集抽样命中象限三：预期非法但接受）；O0 下 `BRANCH_TARGETS` 注释已去重为单条目，O1 起整条 `BRX` 折叠消失 |
| `.branchtargets` 单目标列表 | **接受**（合法边界，非"至少 2 个目标"）；同样因目的地与索引无关，O1 起完全折叠 |
| `.func .noinline` / `.noinline .func`（两个语法位置） | 拒绝，`Parsing error near '.noinline': syntax error`——PTX 9.0 没有函数级内联控制指令 |

## 意外发现

1. **`ptxas` 从不内联 `.func` 调用**，与函数体大小、优化级别无关（单指令 trivial body 在 O3 下依然保留独立 `CALL`/`RET`）。PTX 语法层面也没有 `.noinline`/`.forceinline` 之类的指令——两个语法位置都被硬拒绝为 parse error。这意味着 `__noinline__`/`__forceinline__` 这类 CUDA C++ 属性完全由 nvcc 前端（NVVM）在生成 PTX 之前决定；喂给 `ptxas` 的手写 `.func` 恒定保留为调用，"noinline 控制"这个研究问题在 PTX→SASS 这一层的答案是"不存在这样的控制，因为默认就是不内联"。
2. **uniform 值分析对算子选择敏感**：同一个 warp-uniform 的 kernel 参数值，经 `and.b32`（按位与）处理后仍被识别为 uniform（`brx.idx` 在 O3 lower 为 `BRXU`）；但经 `rem.u32`（取模，走乘法-高位的除法序列）处理后，同样在数学上 uniform 的结果**不再**被识别为 uniform，`brx.idx` 退化为普通 `BRX`（GPR）。这是本次校准里最反直觉的发现——ptxas 的"值一致性"传播不是语义层面的（"这个值对所有线程真的相等吗"），而是句法/数据通路层面的（"这条指令的 lowering 序列是否落在一致值数据通路支持的指令集合里"）。旗舰套件因此统一用 `and.b32` 构造 `register_uniform` 轴，避免把这个已知的算子选择偏置错记成"index_source 轴本身失效"。
3. **`BRXU` 选中的分支合并值不会被下游自动继续判定为 uniform**：手工探针里，第一个 `brx.idx`（uniform 索引，lower 为 `BRXU`）的两个目标块各自写入一个字面常量到同一寄存器，合并后的值理论上仍是 warp-uniform 的，但用它取模构造的第二个 `brx.idx` 索引却被判定为非 uniform（仍是 `BRX`）——`BRXU` 的选择结果并不会把"一致性"标签继续向下游传播过合并点。旗舰套件的 `double_chain` case 为了保证两段都能验证 `BRXU`，改为让两个 `brx.idx` 都直接从同一个原始一致寄存器派生索引（因此套件里观测到的是两个 `BRXU`，与这条手工探针的结果不同，二者并不矛盾：套件验证的是"链式独立索引"场景，这条发现记录的是"索引依赖分支合并值"场景，是另一条尚未纳入套件轴的观测）。
4. **`@%p brx.idx` 从不产生谓词化 `BRX`**：无论 guard 谓词 uniform 还是 divergent，`ptxas` 都把它重构成"skip-branch + 无条件 `BRX`"，而不是尝试在 `BRX` 指令本身上挂谓词。`.func` 内提前 `ret;` 也是同样模式（重构为跳转 + 复制的无条件 `RET`，不是 `@P RET`）——这两个观测放在一起说明：**本族里"终止/多路转移类"指令（`ret`/`brx.idx`）在本工具链上没有观测到任何谓词化形式，只有 `bra`/`exit` 有**。这是一条针对"谓词化"这一 P0-1 邻近问题的结构性边界，值得在后续套件里显式验证是否对全族成立。

## 对抗式审查缺口在本族的落实

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | 本族对应物是重汇聚栈（`BSSY`/`BSYNC`）——已证实其触发条件是"谓词一致性 × 分支体可谓词化性"的合取，不是单一语法特征；旗舰套件的 `guard_uniform`/`guard_divergent` 两个 expanded case 直接对照验证 |
| P0-2 合法面未证伪 | 全部负向探针登记 `expected_diagnostic` 子串（先探针取真实文本再登记）；额外保留 2 条补集抽样（`index_type_f32`、`empty_branchtargets`），并已从补集抽样里捕获一个"预期非法却接受"的真实发现（`duplicate_target`，已移入正向 case 并在文档登记） |
| P0-3 组合不足 | 本族最强的正面回应：同一 PTX 指令因区域上下文不同产生 0/1/N 条 SASS 是直接实测事实，不是理论推断；旗舰套件的 `double_chain` case 覆盖序列级组合（同一 kernel 内两个独立 `brx.idx`），`merge`×`index_source`×`target_count` 三轴全factorial 覆盖单指令层组合 |
| P1-1 模板未受控 | 旗舰套件 `template_wide` case（加宽/打乱参数签名，验证槽位不因模板变化而误判） |
| P1-2 重物化前提 | 旗舰套件 `index_indirect` case（索引从全局内存指针间接装载，不可折叠） |
| P2 边界 | 套件接受 `--ptxas/--nvdisasm` 路径参数；本文全部结论标注 `STATIC_ONLY`，见文末边界声明 |

## 每指令研究重点

### `brx.idx`（A，套件已建，`FRAMEWORK_VALIDATED`）

1. `BRXU` 的一致性传播边界（`rem.u32` vs `and.b32`、跨 `BRXU` 合并点）尚未系统化为轴，只是本文档记录的观测；后续若要把"uniform 索引"轴细分为"经算术 vs 经位运算派生"，需要先把这条边界摸清楚更多算子（`div`、`mul`、`shr` 等）。
2. 越界索引的运行时行为完全未验证（`STATIC_ONLY` 排除范围）；O3 对越界常量索引的 UB 折叠行为本身是否稳定（换一个稍微不同的越界值、换一个不同的目标数）还未做系统扫描，只有单点探针。
3. 嵌套重汇聚桶（`BSSY.RECONVERGENT` + `BSSY.RELIABLE`）的桶分配规则未深入研究——目前只确认了"guard skip 用一个桶、`BRX` 多路汇合用另一个桶"，`RELIABLE` 桶的分配规则、与 `RECONVERGENT` 桶的调度关系需要更多探针。

### `bra`（区域决定型，`DESIGNED`）

1. if-conversion 阈值：多大/多复杂的分支体会阻止谓词化？目前只用"直线代码 vs 含循环"两个极端点做了对照，中间地带（比如含一次不可谓词化的 `ld.global` 但无循环）未探测。
2. `.uni` 后缀在本次探针范围内被证实"不改变编译器决策"，但样本只有 1 组对照，需要更多 uniform/divergent × `.uni`/无 `.uni` 组合确认这是通例还是个例。
3. compare-branch folding（README 门槛提到的优先上下文）——`ISETP` 与 `BRA`/`EXIT` 是否会被折叠进单条谓词生成指令，需要专门探针（当前探针都保留了独立的 `ISETP` + 分支）。

### `call`（稳定配对+区域决定型混合，`DESIGNED`）

1. leaf/non-leaf、间接调用（通过 `.callprototype` 与函数指针）完全未探测，只做了直接调用。
2. 参数/返回值 ABI（多参数、聚合类型、通过内存 vs 寄存器传递）未探测，只用了单个 `.b32` 标量参数和返回值。
3. `call` 与 `brx.idx`/`bra` 一样参与重汇聚机制，但"调用点内部"（callee 内部是否也可能有自己的重汇聚需求，caller/callee 两层重汇聚桶是否冲突）未探测。

### entry/`.func` 级 `ret`（稳定终止 + 区域决定型混合，`DESIGNED`）

1. `.func` 提前 `ret` 的"复制尾部 + 跳转"重构模式只在单个提前返回点上验证；多个提前返回点（3 个以上）是否仍然逐个复制尾部，还是收敛成一个共享出口，未验证。
2. 返回值为聚合类型或多寄存器时的重构行为未验证。
3. entry 级多处 `ret;`（不同谓词路径各自 `ret`）是否也套用相同的"复制 `EXIT`"模式（而不是谓词化 `EXIT` 或统一跳转），需要专门探针——目前只验证了 `exit` 指令本身的谓词化行为，未验证多出口 `ret` 的行为是否与单条 `@%p exit;` 一致。

### `exit`（稳定终止，`DESIGNED`）

1. 谓词化 `exit` 是本族目前唯一确认"零重汇聚簿记"的分支类指令；但只验证了单个谓词分支点，多层嵌套谓词（比如 `@%p1 exit; ... @%p2 exit; ...`）下是否仍然逐条独立谓词化，还是会被合并成一次判定，未验证。
2. `exit` 与 warp 内其他仍在执行的 lane 之间的活跃掩码更新机制属于运行时语义，`STATIC_ONLY` 范围排除，仅记录为待运行时验证的边界。

## 边界声明

全部结论为 `STATIC_ONLY`：编译通过 + 归属成功不证明实际跳转目标选择、warp 收敛的运行时正确性、越界索引的实际执行后果或函数调用栈帧的运行时布局语义。重汇聚栈桶寄存器（`B0`/`B1`）的分配与调度规则、`BSSY.RELIABLE` 与 `BSSY.RECONVERGENT` 的语义差异，均为静态观测记录，不构成对硬件重汇聚算法的完整建模。跨 CUDA release、跨架构（如 `sm_100a`）差分未做，本文全部结论仅对 ptxas V13.0.88 / nvdisasm V13.0.85 / `sm_110a` 成立；套件接受 `--ptxas`/`--nvdisasm` 路径参数，跨版本重跑只需替换工具链路径。
