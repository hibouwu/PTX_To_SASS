# Cluster 与 DSMEM 族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。文中"实测"来自本机校准探针（cluster 支持性判定、mapa 全形态、cvta 全 space × 方向 × 位宽矩阵、其余 opcode 合法性）与已建成旗舰套件 `mapa/thor_ptx90/`（10 syntax + 24 expanded case，O0–O3 共 136 次编译/归属，8 个带诊断锚定的负向探针）的全量自检。探针在会话 scratchpad（含 `cvta_matrix_results.json`）；套件 `suite_spec.py` 文档字符串同步记载校准结论。
> 设计基线：`01_tcgen05` 的静态实验分层与 `02_tma/实验设计.md` 的文档结构，逐条吸收 `01_tcgen05/对抗式审查_实验设计缺口.md` 的 P0/P1 结论。

## 结论

**首要问题的答案：Thor（sm_110a）完整支持 cluster/DSMEM 的编译面。** `mapa`、`getctarank`、`ld/st.shared::cluster`、`isspacep.shared::cluster`、`cvta.to.shared::cluster`、`%clusterid` 全部编译通过。但支持方式与直觉相反——本族在此目标上**没有任何专用 cluster SASS 指令**：

1. **`mapa` 无 MAPA opcode**：合成为 `S2R Rd, SR_CgaCtaId`（自身 rank）+ `LEA`（折入 0x400 类 shared 基址、移到字节 3）+ `PRMT Rd, rank, 0x654, Rd`（把**目标** rank 字节嫁接到规范地址的字节 3）。该结构在 O0–O3、立即数/寄存器/间接 rank、u32/u64 结果、guard 下全部稳定。
2. **规范 shared 地址自带 rank 标签（P0-1 核心事实）**：kernel 带 `.reqnctapercluster` 时，**取普通 `.shared` 符号地址本身**就需要 `S2R SR_CgaCtaId` 把自身 rank 折进 32 位规范地址——没有任何 `mapa` 参与的裸 `ld.shared`/`st.shared` 也会发射它。因此 `S2R SR_CgaCtaId` 不是 mapa 的安全归属锚点；`PRMT`（rank 嫁接步）才是唯一无污染锚点（已在镜像每个上下文轴的脚手架上做基线零命中验证）。这条"上下文改变归属面"的教训与 08 族的尾部 BRA 过匹配同型。
3. **cvta 是分空间的三种机制**：`global` ↔ generic 双向都是**恒等**（零指令，值原样传递——generic 地址就是 global 地址）；`const`/`local` ↔ generic 是 `IADD3±UR 基址` 进位对（to 方向减基址取负，from 方向加）；`shared::cluster` from 方向引入 `S2R SR_SWINHI`（shared 窗口高位），to 方向做低 32 位截取。**u32 形态全族 fatal**："32-Bit ABI is not supported on sm_90 or higher"——cvta 的 32 位地址面在本目标整体不存在（带诊断的合法面发现）。

## mapa 操作数规则（套件级证据）

| 规则 | 实测结果 |
|---|---|
| rank 操作数类型 | 恒为 `.u32`，与 `.type`（u32/u64）修饰的是 `d`/`a` 无关 |
| `.reqnctapercluster` | ptxas **不静态强制**（无该 directive 也编译） |
| 地址来源检查 | 无 provenance 检查（任意 32 位寄存器可作 `a`） |
| rank 立即数越界 | 无编译期检查 |
| `d`/`a` 同寄存器 | 合法 |

以上"预期非法却接受"的形态全部按 P0-2 规则进入正向矩阵（expanded），不作负向。

## 合法面实测

| 探针 | 结果/诊断 |
|---|---|
| 8 条负向探针（类型 token 错、操作数个数、非 shared space 等） | 全部带 `expected_diagnostic` 按预期拒绝 |
| `cvta_*_u32` 全 space | ptxas fatal "32-Bit ABI (--machine 32 or 32-Bit addressing) is not supported on sm_90 or higher architectures" |
| `mapa` 无 `.reqnctapercluster` / 越界 rank / 任意寄存器地址 | 接受（正向 discovery 记账） |

## 审查缺口对应设计

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | 对应物是**规范地址的 rank 标签机制**：`.reqnctapercluster` 的有无改变每一个 shared 地址计算的 lowering（不止 mapa）——launch directive 是真正的"隐藏全局变量"，套件把它与地址来源做交叉轴；`PRMT` 锚点的选择过程本身就是对该机制的系统采样 |
| P0-2 合法面未证伪 | 8 条负向全带诊断；u32 地址面的整体 fatal 是补集抽样产出；mapa 的四条"接受但可疑"形态按预期非法→实测合法流程进正向矩阵 |
| P0-3 组合不足 | rank 来源（立即数/寄存器/间接）× 地址来源（符号直取/偏移/寄存器）× 结果类型 × guard 组合矩阵；expanded 含 mapa 后接 `ld.shared::cluster` 的转换链 |
| P1-1 模板未受控 | expanded 含 `template_wide`；`.reqnctapercluster` 档位对照（P0-1 行）比参数签名更关键 |
| P1-2 重物化前提 | rank 与地址各有间接 producer case |
| P2 边界 | 套件接受 `--ptxas/--nvdisasm` 路径参数；"无专用 cluster 指令、全部软件合成"是最可能随架构代际改变的结论（sm_90 的 Hopper 有 MAPA 指令），跨架构差分价值最高的族之一 |

## 各指令研究重点

- `mapa`（`FRAMEWORK_VALIDATED`）：套件见 [mapa/thor_ptx90/](mapa/thor_ptx90/)；开放问题：`PRMT 0x654` selector 的字节语义完整解码、`LEA` 基址常量的来源表。
- `cvta`（`DESIGNED`）：全矩阵已探（恒等/基址对/窗口寄存器三机制 + u32 全灭）；套件重点是三机制的归属口径（恒等类需 `empty_target_allowed`）与 `07_lsu` generic 寻址研究的交叉引用（结论独立持有）。
- `getctarank`（`DESIGNED`）：合法性已确认；预计是规范地址字节 3 的提取序列（`SHF`/`SGXT` 类），待建表。
- `isspacep`（`DESIGNED`）：合法性已确认；预计是地址窗口比较序列，判定常量表是观测重点。
- `ld.shared-cluster` / `st.shared-cluster`（`DESIGNED`）：合法性已确认；预计落在带 rank 标签的规范地址上的普通 `LDS`/`STS`（无专用远程指令——与 mapa 的合成结论一致），套件需与 `03_mbarrier` 的 remote arrive 交叉核对地址形态。
