## 各种上下文配置文件的含义

- `branched_producers`：改变 `operand_producers` 上下文组。在条件基本块中选择直接参数或 delta 派生 producer。
- `commit_completion`：改变 `completion` 上下文组。单独改变顶层上下文组 completion。
- `compound_predicated_issuer`：改变 `issuer` 上下文组。用 lane 0 与参数谓词的合取直接保护目标指令。
- `derived_producers`：改变 `operand_producers` 上下文组。单独改变生产者链。
- `dynamic_lane_issuer`：改变 `issuer` 上下文组。由 kernel 参数选择发射 lane。
- `enable_false`：改变 `enable_input_d` 上下文组。单独改变 D 累加使能常量。
- `enable_index_sweep`：改变 `enable_input_d` 上下文组。七条代表性核心指令分别使用七个同时活跃的 enable 谓词，以恢复 enable-index 字段。
- `enable_true_mask_ones`：改变 `disable_output_lane+enable_input_d; enable_input_d` 上下文组。这是一个联合处理配置，存在联合效应。
- `global_load_producers`：改变 `operand_producers` 上下文组。从 global-memory load 生成全部目标操作数。
- `guard_negative`：改变 `target_guard` 上下文组。使用负 guard。
- `guard_positive`：改变 `target_guard` 上下文组。使用正 guard。
- `idesc_pair_pressure`：改变 `operand_producers` 上下文组。单独改变一个顶层上下文组。
- `lane0_issuer`：改变 `issuer` 上下文组。限制 lane 0 为发射线程。
- `lane31_issuer`：改变 `issuer` 上下文组。限制 lane 31 为发射线程。
- `nonidentity_producers`：改变 `operand_producers` 上下文组。用参数 delta 构造不能被消除的算术 producer。
- `predicate_index_up0`：改变 `enable_input_d+target_guard` 上下文组。释放 enable 的 UP0 后定向观察核心 guard 的 UP0 编码。
- `predicate_pressure_1`：改变 `target_guard` 上下文组。用统一谓词活跃压力定向观察核心 guard 的 UP1 编码。
- `predicate_pressure_2`：改变 `target_guard` 上下文组。用统一谓词活跃压力定向观察核心 guard 的 UP2 编码。
- `predicate_pressure_3`：改变 `target_guard` 上下文组。用统一谓词活跃压力定向观察核心 guard 的 UP3 编码。
- `predicate_pressure_4`：改变 `target_guard` 上下文组。用统一谓词活跃压力定向观察核心 guard 的 UP4 编码。
- `predicate_pressure_5`：改变 `target_guard` 上下文组。用统一谓词活跃压力定向观察核心 guard 的 UP5 编码。
- `predicate_pressure_6`：改变 `target_guard` 上下文组。用统一谓词活跃压力定向观察核心 guard 的 UP6 编码。
- `thread0_issuer`：改变 `issuer` 上下文组。限制 CTA thread 0 为发射线程。

## 统计口径

- `core`：只比较已经归属的 MMA 核心指令。
- `kernel`：比较整个 kernel，包含参数装载、谓词、分支、操作数准备和完成指令。
- `encoding_changed`：保留具体寄存器编码，不能单独解释为指令选择发生变化。
- `仅重编号`：核心 MMA 使用的具体寄存器号改变，但 R/UR/P/UP 路径和操作数之间的寄存器复用关系不变。
- `类别变化`：区分普通寄存器与统一寄存器以及谓词路径，也区分 RZ、URZ、PT、UPT 等特殊寄存器。
- 活跃寄存器数来自 `nvdisasm --life-range-mode count` 的静态数据流结果。kernel 引用过的寄存器集合不等于硬件分配上限。
- `LDL*`/`STL*` 被记为本地内存指令指标，能提示潜在的寄存器溢出（spill），但仅凭指令名不能断言一定由溢出造成。
- 本报告只描述静态 PTX → SASS 代码生成差分。
