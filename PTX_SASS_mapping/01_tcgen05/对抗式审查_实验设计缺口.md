# tcgen05 实验设计的对抗式审查

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0
> 本文性质：针对现有实验设计的证伪性审查，v2（按外部评审修订）。
> 审查立场：假设现有结论可能是实验设计的产物而非 ISA 事实，逐条尝试推翻。

## 证据状态

本文引用的全部探针已入库：[probes/run_gap_probes.py](probes/run_gap_probes.py) 可一键复现，产物（PTX、cubin、反汇编、逐探针观测）连同工具版本与 SHA-256 存于 `probes/results/summary.json`。引用格式为 `probe:<名称>`。字段级解释（wait 掩码、屏障索引）依赖 [tools/decode_ctrl.py](tools/decode_ctrl.py) 的字段布局假设，该布局沿用 Volta 系公开资料，已在本机多个 kernel 上通过生产者-消费者自洽检查，但在 `sm_110a` 上仍属**待 Thor 复核的假设**，因此本文对 word 1 的表述一律限定为"原始调度/控制字段"。

## 审查结论

现有实验在"单条指令的助记符与修饰符选择"这一层是扎实的。真正的 P0 缺口收敛为三项：

1. 建立调度区域、依赖边与控制字段的生成规则；
2. 建立合法语法全集与四象限验证；
3. 建立以完整固定序列为单位的组合矩阵。

此外存在一个此前遗漏的编译器级缺口（ELF/cubin 装配层，见 P1-4）。运行时语义已由项目口径（`STATIC_ONLY`）显式排除，不再列为缺口。

## P0-1 调度控制字段没有生成规则，只有编码簿

现状：`descriptor_and_encoding.md` 把 word 1 高位记为编译器编码簿（codebook）单独记录，不提供生成规则。

实测（`probe:async_depth`）。同一 semantic form 的 `tcgen05.ld`，只改变调度区域内在飞异步操作的条数——这本身构成不同的调度区域上下文——其 word 1 高位原始字段随之改变：

| 在飞 LDTM 条数 | 各条 LDTM 的 word 1（前两条） |
|---|---|
| 1 | `0x001e62...` |
| 2 | `0x001fe2...`、`0x000e22...` |
| 4 起 | `0x001fe2...`、`0x000fe2...`（后续依位置递变） |

同一 semantic form、不同调度区域上下文，编码不同。决定因素是整个调度区域内异步操作的数量与消费点位置，不是该指令自身的任何字段。因此该字段不可能由逐指令规则表达，必须以调度区域为单位生成。

风险表述（判断而非已证明的结论）：这些字段若生成错误，可能破坏依赖等待；静态规则不能保证生成代码的可执行正确性，且此类错误在反汇编文本中不可见。这是把它列为 P0 的理由。

要做的事：把调度区域作为实验单元，至少三个新轴——在飞异步操作条数、消费点距离、异步操作类型混合（MMA / LDTM / STTM / UTCCP 同时在飞）；并在 Thor 上复核 `decode_ctrl.py` 的字段布局假设。

## P0-2 合法面缺少全集验证

现状：30 个阴性探针全部得到预期拒绝，且已核对诊断信息与出错行号。

问题不在已有检查的质量，而在其覆盖结构：这 30 针证明"这 30 个组合被拒绝"，不能证明"生成矩阵接受的集合恰好等于 ISA 合法集合"。若作者读规范时把某个合法组合误判为非法而排除在生成矩阵之外，现有检查不会报错——它只是安静地不出现在 896 个 semantic form 里。

要做的事：先定义有限的语法候选全集（各限定符轴的全笛卡尔积减去已知约束），再系统枚举或 mutation，把每个候选归入四象限并分别记录：

| 象限 | 含义 | 处置 |
|---|---|---|
| 预期合法且接受 | 覆盖确认 | 入正矩阵 |
| 预期非法且拒绝 | 边界确认 | 入阴性目录 |
| 预期非法但接受 | **合法面画小了** | 修正约束模型，重算覆盖 |
| 预期合法但拒绝 | **合法面画大了** | 修正约束模型 |

后续在指令套件上的抽查（见[各指令套件对抗式审查.md](各指令套件对抗式审查.md)）已经找到象限三的实例：`tcgen05.dealloc ncols=96` 合法但不在任何套件的轴上。

## P0-3 缺少以序列为单位的组合矩阵

现状：semantic form 层有 896 个形态，跨指令层只有 8 个 effect slice。二者不是同一层对象，不能写成覆盖比例；正确的表述是：**当前只有 8 个跨指令 effect slice，尚未形成序列语法与组合矩阵**。而项目目标（"顺序固定的固定 PTX 搭配"）的重心恰在序列层。

序列层需要回答而单指令矩阵无法回答的问题：

- 两条 MMA 背靠背且 collector 为 fill 到 use，编译器是否重排、是否保持两条独立指令
- `alloc` 到 `mma` 到 `commit` 到 `dealloc` 全生命周期中，各段簿记代码是否合并
- 多族 tcgen05 指令共存时 UR 槽位与 SMEM 影子状态是否互相挤占
- `tcgen05.cp` 与 `tcgen05.mma` 共用 TMEM 时的 commit 归属

实测（`probe:splice`）表明序列还不可拆分复用。同一段代码单独编译与拼在另一段之后编译，其 word 1 不同：

| 情形 | 该段 STG 的 word 1 |
|---|---|
| 单独编译（segB） | `0x002fe2...` |
| 拼在 segA 之后（segAB 第二条） | `0x000fe2...` |

编译器根据前缀已满足的依赖消除了冗余等待。把在"有前缀"上下文里录制的模板贴到新上下文会缺少必要等待。推论：可安全复用的最小单位是完整序列；序列矩阵不是锦上添花，而是模板复用正确性的前提。

## P1-1 固定 kernel 模板影响物理编号，不影响已冻结的槽位 bitfield

实测（`probe:template_idesc`）。仅把 idesc 从 kernel 参数改为编译期常量，物理 UR 编号整体重排：

| 操作数 | idesc 来自参数 | idesc 为常量 |
|---|---|---|
| A / B | `gdesc[UR10]` / `gdesc[UR12]` | `gdesc[UR6]` / `gdesc[UR8]` |
| D / aux | `tmem[UR8]` / `tmem[UR4]` | `tmem[UR4]` / `tmem[UR10]` |
| idesc | `idesc[UR5]` | `idesc[UR11]` |

范围限定：这只推翻"固定物理 UR 编号"，**不触及已冻结的五个编码槽位的位置**（A：word 0 `[31:24]`；B：word 0 `[39:32]`；D：word 1 `[7:0]`；auxiliary：word 0 `[47:40]`；extra：word 0 `[55:48]`）。换模板改变的是字段值，不是字段位置。

因此规则文档须分开登记：槽位 bitfield 位置与角色顺序是 ISA 层结论；物理编号只是该模板的观测记录，不得写成规则。仍要做的事：用至少三种签名（参数少、参数多、顺序打乱）确认槽位位置与角色顺序在换模板后不变。

辅助对照（`probe:reqntid`）：`.reqntid` 取 32/128/省略，核心 MMA 完全不变，该隐藏变量对 mma 可排除；alloc 族含 `ELECT`/`WARPSYNC.ALL`，需单独验证后才能一并排除。

## P1-2 "槽位稳定源于重物化"降级为待验证假设

实测（`probe:ur_reuse`）：12 条各带独立描述符的 MMA 复用同一组 UR4–UR10（max UR 10），编译器插入 32 条 LDCU 逐条重装载。这与"操作数可从常量 bank 廉价重物化，因此槽位表现稳定"一致。

但这只是与观测一致的假设，不是已证明的因果结论：v4 的上下文矩阵已各含 1,152 个 nonidentity、branched 与 global-load producer（见 `context_lowering.md`），操作数并非全部来自常量 bank，而这些 case 的核心槽位行为并未表现出崩坏。真正尚未覆盖、可能打破该假设的形态是：循环携带的描述符、位域拼装产生的描述符、不可重物化的描述符长距离存活、多条 MMA 跨区间存活竞争 UR 文件。

要做的事：用上述四类形态构造 case，观察 UR 分配是否仍收敛到固定槽位组；在此之前本条仅作为假设记录。

## P1-3 LDL/STL 观测的适用范围应显式标注

现状核实：现有文档只把"未观察到 LDL/STL 变化"写成观测指标，并明确"仅凭 LDL/STL 不能断言 spill"，没有把"未出现"升级为规则。此前审查对此的批评过重，予以修正。

保留的技术点（`probe:gpr_pressure`）：200 个跨 MMA 活跃值把 GPR 压到 R165 仍零 LDL/STL，核心 MMA 不变——因为 MMA 操作数在 UR 空间，与 GPR 压力正交。因此该观测对"分配器压力影响 MMA"既不构成肯定也不构成否定。建议仅是：在文档中给这条观测补一句适用范围（GPR 压力域，不含 UR 压力域），或补一个真正压满 UR 文件的 case。

## P2-1 复现证据的准确表述

现状核实：v3 已在同一 CUDA 13.0 release 内两份不同 SHA 的工具链二进制上复现（见 `reproducibility.md`），并非没有稳定性轴。准确的缺口表述是：

- v4 新增的机制（操作码复合字段、槽位压力见证等）目前只有单二进制证据；
- 尚无跨 CUDA release 的验证；
- 尚无跨架构（如 `sm_100a`）差分，无法区分"ISA 事实"与"本版本 ptxas 的实现选择"。

对一份要长期使用的规则集，跨 release 差分决定保质期，优先级中等。

## P1-4 （新增）ELF/cubin 装配层缺口

若目标是直接产出可执行 cubin 而不只是 SASS 文本，则指令选择与控制字段之外还有一整层未研究：ELF/code object 布局、kernel metadata（`EIATTR_*`：REGCOUNT、FRAME_SIZE、PARAM_CBANK、KPARAM_INFO 等）、寄存器计数申报、符号与重定位、控制字段到 128-bit 指令字的装配。DocumentSASS 截获物中已见这些节区标记，但项目对其零建模。该缺口比运行时语义更应列入清单：它是"生成的东西能否被驱动加载"的前提。

要做的事：以 ptxas 产物为参照，diff 最小 kernel 的 ELF 节区与 metadata，建立最小可加载 cubin 的装配清单。

## 范围说明（非缺口）

- **运行时语义**：项目口径为 `STATIC_ONLY`，运行时语义显式排除，不列为缺口。保留一条范围备注：alloc 族 lowering 中 ptxas 自行插入 `BPT.TRAP` guardrail 与三个具名 trap stub，说明部分约束被 NVIDIA 设计为运行时检查；静态结论不覆盖这一层。
- **描述符不透明**：是正确的范围裁决。实测常量 idesc 经 `UMOV` 入寄存器而不折叠进立即数字段，核心形态不变；编译器无需理解描述符内部。

## 修订后的处理顺序

| 优先级 | 事项 | 理由 |
|---|---|---|
| P0 | 调度区域/依赖边/控制字段的生成规则 | 逐指令规则结构性表达不了 |
| P0 | 合法语法全集与四象限验证 | 已发现象限三实例 |
| P0 | 以完整序列为单位的组合矩阵 | 模板复用正确性的前提（splice 证据） |
| P1 | ELF/cubin 装配层建模 | 可执行产物的前提 |
| P1 | 三种签名验证槽位位置稳定性 | 区分 ISA 事实与模板产物 |
| P1 | 四类不可重物化形态验证 P1-2 假设 | 假设未证 |
| P2 | 跨 release 与跨架构差分 | 规则集保质期 |
| P2 | LDL/STL 观测补适用范围标注 | 文档准确性 |
