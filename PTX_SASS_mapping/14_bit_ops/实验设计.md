# Bit operations 族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。文中"实测"来自本机 bit 族校准探针（lop3 全形态、其余 9 opcode 代表形态、immLut/位段立即数边界枚举）与已建成旗舰套件 `lop3/thor_ptx90/`（37 syntax + 61 expanded case，O0–O3 共 392 次编译/归属，15 个带诊断锚定的负向探针）的全量自检。探针在会话 scratchpad；套件 `suite_spec.py` 文档字符串同步记载校准结论。
> 设计基线：`01_tcgen05` 的静态实验分层与 `02_tma/实验设计.md` 的文档结构，逐条吸收 `01_tcgen05/对抗式审查_实验设计缺口.md` 的 P0/P1 结论。族 README 的"立即数类别不能只取单个代表值"高风险簇声明是本族套件的组织原则。

## 结论

旗舰 `lop3` 的校准推翻了"immLut 原样透传"这一直觉假设，并确立了三条对逆向映射至关重要的规则：

1. **immLut 槽位置换**：硬件只在物理第二源槽有立即数位。PTX 立即数写在 `b` 槽时 immLut 原样透传；写在 `a` 或 `c` 槽时，ptxas 交换寄存器操作数并**代数置换 immLut** 使三输入真值表不变（不对称探针 LUT `0x30`：a 槽立即数 → SASS immLut `0xc`，c 槽 → `0x50`，b 槽 → `0x30` 不变）。逆向方向必须先解出置换才能还原 PTX immLut。PTX 字面 `0` 不按立即数处理——直接编码为 `RZ` 寄存器，无重排无置换，因此"零值"是独立于"寄存器/立即数"的第三操作数类。
2. **越界静默截断（P0-2 发现）**：immLut/immLut2 不做 8 位静态范围检查——`0x100` 编译通过并截断为 `0x0`，`-1` 回绕为 `0xff`。"预期非法却接受"的两个发现已按 P0-2 流程进入正向矩阵（`discovery_*` CTX）而非负向。多重立即数源合法：ptxas 用 `MOV` 物化多余字面量，编码里恒只留一个真立即数。
3. **BoolOp 一对二 lowering**：`lop3.BoolOp.b32 d|p, a, b, c, immLut, immLut2` 是 PTX 9.0 真实语法（`BoolOp ∈ {.and, .or}`，`.xor` 显式拒绝；`lop3.and.b32` 与 `lop3.b32.and` 两种修饰符顺序均接受——与 02_tma 的 `cta_group` 位置发现同型）。`d` 与 `p` 都被消费时一条 PTX lower 成**两条** `LOP3.LUT.PAND`（值形态 + 谓词形态）；`p` 不消费则只剩值形态。immLut2 的数值从未在 SASS 编码中观察到，唯一可观测效应是 immLut2=0 时尾谓词字面量从 `PT` 翻为 `!PT`——登记为 STATIC_ONLY 开放问题，不作语义结论。

其余结构事实：guard 不存活（无条件计算 + `SEL` 合并，与 17 族 dp4a、18 族 tanh 的 guard 结论同型）；重复源合法（单条 `LOP3.LUT` 多槽同寄存器）；O0 不 CSE、O3 对文本相同的双 lop3 合并（`dedup_o3` case——**每 O 档目标出现次数不同是预期行为**，归属逻辑必须按 O 档分别记账）。

## 合法面实测（负向探针，全部带诊断锚定）

| 探针 | 诊断类别 |
|---|---|
| `lop3.b64` / `.u32` / `.f32` / `.b16` | "Unexpected instruction types"——lop3 在本目标上 **`.b32`-only**，四种错误类型 token 同一诊断 |
| 缺 immLut / 缺 c 操作数 / 5 参数无 BoolOp / BoolOp 缺 immLut2 | "Arguments mismatch" 组 |
| immLut / immLut2 用寄存器 | "Arguments mismatch"（立即数槽不接受寄存器） |
| `lop3.xor.b32`（BoolOp 只有 and/or） | 显式拒绝 |
| 臆造 BoolOp 修饰符 / 双 BoolOp | "Unknown modifier" / 重复修饰符诊断 |
| 源操作数一元取负 `!`/`-` | "Operand negation not allowed for instruction 'lop3'"——**取负必须折进 LUT 值本身**，没有操作数修饰位 |
| 无 BoolOp 却写谓词目的 | 独立诊断 |
| 补集抽样：双 BoolOp 叠写（`lop3.and.or.b32`） | "Multiple instruction post-operation flags set" |
| 补集抽样：immLut2 用寄存器 | "Arguments mismatch for instruction 'lop3'" |

15 条负向探针中最后两条是假定合法面之外的补集抽样（P0-2）；immLut 越界（0x100/-1）原本也属补集候选，因实测被接受而按流程转入正向 `discovery_*` 坐标。

## 审查缺口对应设计

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | 本族对应物是**立即数编码类 + 槽位置换**：同一 PTX immLut 因立即数所在槽位产生三种 SASS 编码——"编码由指令外因素决定"的 bit 族形态；immLut 档位按高风险簇声明取 {0x00, 0xff, 0xaa, 0x30(不对称), 0x96, 0xe8, 0x1a} 多档而非单代表值 |
| P0-2 合法面未证伪 | 15 条负向探针全带 `expected_diagnostic` 且按约束类型分组；immLut 越界截断与 BoolOp 语法是两组"预期非法却接受"发现，均入正向矩阵 `discovery_*` CTX；immLut2 的编码去向登记为开放问题而非硬写结论 |
| P0-3 组合不足 | 操作数三槽 × {寄存器/立即数/零/重复源} 组合矩阵；双 lop3（O0/O3 CSE 差分）与 BoolOp 双目的消费组合显式在矩阵内 |
| P1-1 模板未受控 | expanded 含 `template_wide` |
| P1-2 重物化前提 | 操作数间接 producer case（内存装载源）；消费者一律直接 `st.global` 落地——族 README 高风险警告的直接落实（xor/and 汇聚会以 `LOP3` 自污染归属，基线零命中检查据此设计） |
| P2 边界 | 套件接受 `--ptxas/--nvdisasm` 路径参数；immLut 置换规则与截断行为是纯 ptxas 实现选择，跨版本重跑最优先复核 |

## 各指令研究重点

- `lop3`（`FRAMEWORK_VALIDATED`）：套件见 [lop3/thor_ptx90/](lop3/thor_ptx90/)；开放问题：immLut2 的编码去向、`PAND` 尾谓词翻转的语义。
- `prmt`（`DESIGNED`）：mode → 修饰符映射已探；重点是通用 selector 立即数的编码类（每 nibble 语义）与 mode 缺省形态。
- `bfe`/`bfi`（`DESIGNED`，序列类）：**本目标无独立 BFE/BFI 指令**，是 `SGXT`/`SHF`/`LOP3` 组合；位置/宽度档位 {0,1,8,31,32,越界} 的序列结构差分是套件主轴；越界值是静态拒绝还是编码保留需逐档定论。
- `popc`/`clz`/`bfind`/`brev`（`DESIGNED`）：b32 单指令直译，b64 拆对；`clz`↔`FLO` 的语义修正序列与 `bfind.shiftamt` 的常量差分是重点。
- `bmsk`（`DESIGNED`）：`.clamp`/`.wrap` → `.W` 位，直译类。
- `fns`（`DESIGNED`，序列类）：无专用指令，序列模板按 B 类方法建表。

## STATIC_ONLY 边界声明

本文与套件的全部结论限于静态编译与反汇编。immLut 置换的数值等价性、越界截断后的实际真值表、immLut2 的运行时语义都需要运行时 oracle 验证，不在本轮 PASS 含义内。
