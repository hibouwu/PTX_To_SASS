# BF16 族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。全部结论来自本机 scratchpad 中独立编写的 bf16 探针（三轮，约 90 个候选 kernel）的 O0–O3 编译反汇编，以及已建成套件（`fma/thor_ptx90`，8 syntax + 25 expanded case）的全量自检。**没有引用 `11_half_precision`（F16 族）的任何探针、套件或结论**——该族尚未建立探针，本文档不依赖其存在，也不假设 F16 的表面 pattern 对 BF16 成立（见 `README.md` 完成门槛）。
> 设计基线：`01_tcgen05` 的静态实验分层与 `02_tma/实验设计.md` 的裁决结构，逐条吸收 `01_tcgen05/对抗式审查_实验设计缺口.md` 的 P0/P1 结论。

## 结论

BF16 族 10 个 opcode 全部落在"单指令直译"框架内（每条 PTX 指令产生 1 条或一条固定长度的 SASS 序列，没有 tcgen05 式的多指令生命周期协议），但直译目标本身分裂成三条路径，且**分裂边界不是按 opcode 家族（加/乘/比较）划分，而是按每个 opcode 各自实测决定**——这正是本文档存在的原因：

| 路径 | 特征 | 覆盖 opcode（本次实测） |
|---|---|---|
| A 原生 x2 直译 | 标量与 packed 共用同一枚 `H*2.BF16_V2` 硬件单元；标量借 selector（`.H0_H0`/`.H1_H1`）把两个不同的标量数广播打包进同一个 32-bit 寄存器的两个 lane 后直译，packed 直接整字操作 | `add`、`sub`（借道 `HADD2` 取负操作数，无独立 `HSUB2`）、`mul`、`min`、`max`、`abs`/`neg`（借道 `HFMA2` 恒等式，无独立 `HABS2`/`HNEG2`）、`set`、`setp`、`fma`（仅 `.rn` 且仅当 dtype 为 `bf16x2`，或 dtype 为 `bf16` 且 `.rn`） |
| A' F32 模拟序列（**仅 `fma` 标量、仅非 `.rn` 舍入**） | 每个操作数经 `HADD2.F32` 展宽为 f32，`FFMA.RZ`/`FFMA.RM`/`FFMA.RP` 以请求的舍入模式做乘加，再经 `F2F.F16.F32` 收窄回 bf16 | 仅 `fma.rz/.rm/.rp.bf16`（标量） |
| — 该拆分不存在的证据 | `fma.rz/.rm/.rp.bf16x2`（packed）编译通过但 SASS 与 `.rn` **逐位相同**（`0x0000000200007231` / `0x003fde0000200003` 三种舍入 token 全同）——舍入 token 在 packed 路径上被静态接受但语义上被忽略，只有标量路径真正切换到模拟序列 | `fma`（packed） |

这条"fma 标量路径按舍入 token 分叉、packed 路径不分叉"的发现，是对"预期非法却编译通过"（P0-2）与"预期合法却按同一方式处理"两类假设同时证伪的实例：读规范容易假设 bf16 fma 和 add/sub/mul 一样只接受 `.rn`（`add.rz.bf16` 等确实被拒绝，见下表），但探针直接推翻了这个假设——只有 `fma` 接受 `.rz/.rm/.rp`，且标量与 packed 对同一 token 的反应完全不同。旗舰套件 `fma/thor_ptx90` 的 `results/expanded/sass/sass_attribution.jsonl` 把这三条路径的 100 条归属记录都留在证据里（见"已建套件"一节的按 dtype×rounding 分布统计）。

## 实测助记符总表（10 opcode）

标量列使用 `.b16` 寄存器，通过 selector 借道同一枚 x2 单元；packed 列使用 `.b32` 寄存器直接整字操作。除非另注明，"标量"与"`x2`"在同一探针轮里对照编译，结论并列。

| PTX opcode | 标量（`.bf16`）SASS | packed（`.bf16x2`）SASS | 备注 |
|---|---|---|---|
| `add` | `HADD2.BF16_V2 Rd, Ra.H0_H0, Rb.H1_H1` | `HADD2.BF16_V2 Rd, Ra, Rb` | `.rn` 可省略，省略与显式 `.rn` 编码逐位相同（`0x3000000000007230`/`0x003fde0000200800`） |
| `sub` | `HADD2.BF16_V2 Rd, Ra.H0_H0, -Rb.H1_H1` | `HADD2.BF16_V2 Rd, Ra, -Rb` | **无独立 `HSUB2`**；`sub.bf16` 是合法 PTX opcode，但 SASS 复用 `add` 单元的取负操作数编码位 |
| `mul` | `HMUL2.BF16_V2 Rd, Ra.H0_H0, Rb.H1_H1` | `HMUL2.BF16_V2 Rd, Ra, Rb` | 与 add 同构，`.rn` 同样可省略 |
| `fma`（`.rn`） | `HFMA2.BF16_V2 Rd, Ra.H0_H0, Rb.H1_H1, Rc.H0_H0` | `HFMA2.BF16_V2 Rd, Ra, Rb, Rc` | **`.rn`/舍入 token 强制显式**（省略报 `Rounding modifier required for instruction 'fma'`，add/sub/mul 无此要求） |
| `fma`（`.rz`/`.rm`/`.rp`，标量） | `HADD2.F32`×3（展宽）→ `FFMA.RZ`/`RM`/`RP` → `F2F.F16.F32`（收窄） | — | 唯一从"直译"降级为"多指令模拟序列"的组合；`.sat`/`.ftz` 在该路径上依旧非法（先于路径选择被拒绝） |
| `fma`（`.rz`/`.rm`/`.rp`，packed） | — | `HFMA2.BF16_V2 Rd, Ra, Rb, Rc`（与 `.rn` **逐位相同编码**） | 舍入 token 被语法接受但对 packed 路径无编码影响——仅静态观测，不构成运行时舍入行为声明 |
| `min` | `HMNMX2.BF16_V2 Rd, Ra.H0_H0, Rb.H1_H1, PT` | `HMNMX2.BF16_V2 Rd, Ra, Rb, PT` | 与 `max` 共用同一枚 `HMNMX2` 单元，仅末尾谓词极性不同 |
| `max` | `HMNMX2.BF16_V2 Rd, Ra.H0_H0, Rb.H1_H1, !PT` | `HMNMX2.BF16_V2 Rd, Ra, Rb, !PT` | 同上，`!PT` |
| `abs` | `HFMA2.BF16_V2 Rd, -RZ.H0_H0, RZ.H0_H0, \|Ra\|.H0_H0` | `HFMA2.BF16_V2 Rd, -RZ.H0_H0, RZ.H0_H0, \|Ra\|` | **无独立 `HABS2`**；借道 FMA 恒等式 `(-0)×0+\|a\|` 合成，`c` 操作数槽位承载 abs 修饰 |
| `neg` | `HFMA2.BF16_V2 Rd, -RZ.H0_H0, RZ.H0_H0, -Ra.H0_H0` | `HFMA2.BF16_V2 Rd, -RZ.H0_H0, RZ.H0_H0, -Ra` | **无独立 `HNEG2`**；同上恒等式，`c` 操作数槽位承载 neg 修饰 |
| `set`（整型 dtype，如 `.u16`/`.u32`/`.s16`/`.s32`） | `HSET2.BF16_V2.{CMP}.{BOOL} Rd, Ra.H0_H0, Rb.H1_H1, Pc` | `HSET2.BF16_V2.{CMP}.{BOOL} Rd, Ra, Rb, Pc` | 3 操作数 `.BoolOp` 形式（`d,a,b,c`）已验证合法 |
| `set`（浮点 dtype `.bf16`） | 上一行 + `PRMT`/`IABS`/`I2F.BF16.S16` 后处理 | — | 需要把 0/−1 整型比较结果转换成字面 `1.0`/`0.0` 的 bf16 位型 |
| `set`（`.bf16x2` dtype，仅当 stype 也是 `.bf16x2`） | — | `HSET2.BF16_V2.BF.EQ.AND Rd, Ra, Rb, PT` | packed 浮点布尔输出直接在助记符加 `.BF` 后缀，硬件级完成，无需后处理 |
| `setp`（标量，单谓词） | `HSETP2.BF16_V2.{CMP}.{BOOL} Pd, PT, Ra.H0_H0, Rb.H1_H1, Pc` | — | |
| `setp`（`x2`，双谓词 `p\|q`，lane 值互异时） | — | `HSETP2.BF16_V2.{CMP}.{BOOL} Phi, Plo, Ra, Rb, Pc` 后接 `PLOP3.LUT` ×2 归一化 | **单条指令同时产出两个谓词**（原生双输出），`PLOP3.LUT` 把 SIMD 比较位归一化成干净的 0/1 谓词；探针必须让两个 lane 取真正不同的值且两个谓词都被消费，否则 O0 也会把未消费的 lane 判定省略 |

## bf16 立即数写法与 SASS 编码

- 唯一被接受的立即数语法是**裸十六进制位型**：`mov.u16 %h, 0x3F80;`（`0x3F80` 是 bf16 值 `+1.0` 的原始 16-bit 位型——bf16 与 f32 共享指数域，`0x3F80` 正是 f32 位型 `0x3F800000` 的高 16 位截断）。
- `0h3F80`（f16 风格的短浮点前缀字面量）在本工具链上被拒绝：`Parsing error near 'h3F80': syntax error`，对 `.reg .bf16` 和 `.reg .b16` 目标寄存器一致。因此本族所有探针/套件一律使用 `0x` 裸十六进制写法，不使用 `0h` 前缀。
- 立即数**不能直接写进算术指令的源操作数位置**：`add.bf16 %d, %a, 0x4000;` 被拒绝（`Arguments mismatch for instruction 'add'`），必须先 `mov` 进寄存器。`fma` 的 `c` 操作数同样不接受立即数直接量（已登记为 `fma` 套件的补集抽样负向探针）。
- ptxas 自身在 O2/O3 常量传播后，会把寄存器操作数折叠进 SASS 指令的立即数编码槽位——此时 `nvdisasm` 打印的是**十进制浮点字面量**而非十六进制位型（如 `HADD2.BF16_V2 R0, R0.H0_H0, -2, -2`、`HFMA2.BF16_V2 R0, R0.H0_H0, R0.H1_H1, -1, -1`），这是反汇编器的显示约定，不代表 PTX 允许该写法。

## rn / ftz / sat 支持面实测

| opcode | 舍入修饰符 | `.ftz` | `.sat` | 备注 |
|---|---|---|---|---|
| `add` / `sub` / `mul` | 仅 `.rn`，且可省略（省略与显式编码逐位相同） | 非法（`Illegal modifier '.ftz' for instruction 'add'`） | 非法 | `.rz`/`.rm`/`.rp` 一律 `Illegal rounding modifier for instruction '<op>'` |
| `fma` | **强制显式**，且**唯一接受 `.rz`/`.rm`/`.rp`** 的 opcode（触发标量 F32 模拟路径，packed 路径静态无变化） | 非法，在原生路径与模拟路径上都非法（含复合抽样 `fma.rz.sat.bf16`） | 非法，同上 | 省略舍入报 `Rounding modifier required for instruction 'fma'`；重复舍入 token 报 `Multiple rounding modifiers specified` |
| `min` / `max` | 不适用（无舍入语法位） | 非法 | 不适用（无 `.sat` 语法位） | `.NaN` 合法独立存在（→`.NAN` 后缀）；`.xorsign` 与 `.abs` **互相要求**（`Modifier '.xorsign' requires modifier '.abs'` / 反之亦然），二者同时出现时才合法，映射为 `.XORSIGN` 后缀 + 操作数 `\|a\|` 修饰 |
| `abs` / `neg` | 不适用 | 非法 | 不适用 | 无其他修饰符位；PTX 层面 `\|a\|`/`-a` 操作数修饰符**不能**直接折进 `add`/`sub`/`mul`/`fma` 的操作数（解析期拒绝，`Illegal argument to unary minus` / `Operand negation not allowed for instruction '<op>'` / `Parsing error near '\|'`）——只有 `min`/`max` 接受操作数级 `\|a\|`（且必须搭配 `.abs.xorsign` 指令级修饰符） |
| `set` / `setp` | 不适用 | 非法（两者一致） | 不适用 | dtype 枚举比通用 `set` 语法窄：`stype=bf16` 时 dtype 只接受 `u16/s16/u32/s32/bf16/bf16x2`（`bf16x2` 仅当 stype 也是 `bf16x2`），`f16/f32/f64/u64` 一律 `Unexpected instruction types specified for 'set'` |

一个贯穿全族的强规则：**`.ftz` 在本次实测的全部 8 个算术/比较 opcode、全部舍入路径上都非法**，没有一个例外（含 `fma` 的模拟路径复合抽样）。这与"BF16 的 rounding/ftz 支持面应该比 F16 窄"的预期方向一致，但窄的程度和边界（尤其是 `fma` 例外地接受非 `.rn` 舍入）必须以本文实测为准，不得从 F16 已知行为外推——这正是族完成门槛要求的独立作答。

## 结构分类

沿用 `01_tcgen05` 的四类框架并按本族实测收窄：

| 类别 | opcode | 说明 |
|---|---|---|
| A 单指令直译（标量借道 selector） | `add`、`sub`、`mul`、`min`、`max`、`set`、`setp`、`fma.rn`（含 `fma.{rz,rm,rp}.bf16x2`，静态与 `.rn` 同编码） | 1 条 PTX → 1 条 SASS，标量与 packed 共用同一硬件单元 |
| A' 单指令直译但借道恒等式（无独立助记符） | `abs`、`neg` | 1 条 PTX → 1 条 `HFMA2.BF16_V2`，靠恒等式 `(-0)×0+{±\|a\|}` 合成，没有独立 SASS opcode |
| A'' 多指令模拟序列（仅一种组合） | `fma.{rz,rm,rp}.bf16`（标量） | 1 条 PTX → 4 条 SASS（3×展宽 + 1×FFMA + 1×收窄，共 5 条含收窄）；本族里唯一偏离"1 条 PTX→1 条 SASS"的组合 |
| C 完成节点 / B 编译器合成协议 / D 零指令调度约束 | 无 | 本族没有异步协议、没有跨指令生命周期状态机，tcgen05/TMA 的这三类框架在此不适用 |

没有 B/C/D 类意味着本族不需要 TMA 式的"序列上下文矩阵"作为主轴——每个 opcode 的正确性完全由单条指令的操作数/修饰符合法性决定，P0-3（组合覆盖）落在修饰符组合而非跨指令序列上。

## 已校准合法面

- **rounding**：见上表；`fma` 是唯一例外。
- **ftz**：全族全部非法，无一例外（8 个 opcode 独立验证，另 2 个通过 `.ftz` 语法结构相同直接排除）。
- **sat**：全族全部非法（`add/sub/mul/fma` 独立验证；`min/max/set/setp/abs/neg` 无 `.sat` 语法位，不适用）。
- **min/max 的 `.abs`/`.xorsign`**：互相要求，缺一不可；`.NaN` 独立存在。
- **`set` 的 dtype 枚举**：`{u16, s16, u32, s32, bf16, bf16x2}`（`bf16x2` 仅当 stype 也是 `bf16x2`），比通用 `set.CmpOp.dtype.stype` 语法允许的完整 dtype 集合（含 `f16/f32/f64/u64` 等）窄——这是"规范阅读会算宽"的一个实例（P0-2）。
- **操作数修饰符折叠**：`add/sub/mul/fma` 一律拒绝 `-a`/`\|a\|` 直接写进操作数；`min/max` 接受 `\|a\|`（仅搭配 `.abs.xorsign`）。PTX 层面 `neg.bf16` 后接 `add.bf16` **不会**被 peephole 融合成一条带取负操作数的 `HADD2`（O0、O3 均验证保持两条独立指令）——"neg/abs 折叠"假设在 PTX-to-SASS 这一层被推翻，只在 `add` 内部对**寄存器减法**（`sub`）生效，对跨指令的 `neg`+`add` 不生效。
- **打包 producer**：`mov.b32 %rd, {%rh0, %rh1};` 合法，用于从两个独立来源的 `.b16` 值构造非退化（两个 lane 值不同）的 `bf16x2` 操作数；反方向 `mov.b16 {%rh0, %rh1}, %r32;`（拆包）在本工具链上被拒绝（`Arguments mismatch for instruction 'mov'`），因此本族没有 PTX 层面的拆包路径，`f32_cvt_consumer` 类场景只对标量 `bf16` 开放。
- **`setp` 双谓词 `p|q`**：真正的双 lane 独立比较需要两个 lane 输入值不同**且**两个目的谓词都被消费；否则观测到编译器只对一个 lane 做比较后把另一个谓词处理为该结果的归一化重复（退化观测，已在套件设计说明中排除，不写入结论）。

## 审查缺口对应设计

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | 本族没有异步调度区域，将该缺口在 ALU 语境下改写为"控制字/调度上下文是否随消费距离和并发在飞指令数变化"：`fma` 套件的 expanded 内置 `consumption_distance_8`（消费前插入 8 条无关填充指令）与 `parallel_depth_4`（4 条独立 fma 同时在飞后归并消费）两条上下文轴；runtime 保留全函数 128-bit 编码（`full_instructions`），控制字差分不需要重跑实验 |
| P0-2 合法面未证伪 | 负向探针登记 `expected_diagnostic` 子串（先探针取真实诊断文本再登记）；`fma` 套件额外含 2 条明确标注为"补集抽样"的探针（立即数直接做 `c` 操作数、`.rz` 路径上 `.sat` 复合抽样），且本文档已把两个"预期非法却编译通过"的发现（`fma.rz/.rm/.rp.bf16` 本体、`min/max` 的 `\|a\|` 操作数修饰符）写入正向结论而非负向列表 |
| P0-3 组合覆盖 | 修饰符组合不止单因素：dtype × rounding 全笛卡尔积（`fma` 8 种合法组合）已覆盖；`min`/`max` 的 `.NaN`/`.xorsign`/`.abs` 三修饰符组合已按互相依赖关系枚举穷尽（`{}`, `.NaN`, `.abs.xorsign`, `.abs.NaN.xorsign` 四种合法形态，另 2 种非法形态各自登记诊断） |
| P1-1 模板未受控 | `fma` expanded 含 `template_wide`（加宽/打乱参数签名）case，dtype 各一 |
| P1-2 重物化前提 | `fma` expanded 含 `producer_indirect`（操作数经 `ld.global` 而非 `mov` 立即数产生，不可折叠）case，dtype 各一；另有 `lane_asymmetric_pack`（打包 producer，非退化双源）case |
| P2 边界 | 全部结论声明 `STATIC_ONLY`；套件接受 `--ptxas`/`--nvdisasm` 路径参数，跨版本重跑只需换工具链 |

## 每指令研究重点

### `add`（A，套件待建）

1. `.rn` 省略与显式在 O0–O3 全部编码位一致，已确认非语法糖之外的差异；仍需在更宽的操作数上下文（非常量输入）下复核该结论是否受操作数来源影响。
2. 标量借道 selector 的 `PRMT` 打包指令在 O3 是否总是出现，或在特定寄存器分配下被消除，需要更大规模上下文枚举。
3. `sub` 与 `add` 共用同一 SASS 单元（见下），故 `add`/`sub` 建议合并进同一 `add` 或 `sub` 套件的负向探针集合互相复用诊断文本对照，而不是各建一份。

### `sub`（A，与 `add` 同目录，套件待建）

1. 核心问题已确认：不存在独立 `HSUB2`，`sub.bf16` 始终是 `HADD2.BF16_V2` 加取负操作数编码位。需要补一个"编译器是否会把 `sub.bf16 d,a,b` 与手写 `add.bf16 d,a,neg(b)`（若后者可表达）统一到同一 inverse 签名"的规则挖掘验证，但由于 `neg` 不能操作数折叠进 `add`（见上），后者在 PTX 层面无法表达，此问题在当前 ISA 下无法构造对照，记为不可测边界而非缺口。
2. `sub` 是否存在操作数顺序无关的编码差异（`a-b` vs 借道 `a+(-b)` 在 `b` 为立即数折叠常量时是否走同一编码路径）需要 O2/O3 常量折叠场景补充。

### `mul`（A，套件待建）

1. 与 `add` 同构（`.rn` 可省略、无 ftz/sat/其他舍入），核心风险是确认 `HMUL2.BF16_V2` 与 `HADD2.BF16_V2` 是否共享同一控制字段布局（供 P0-1 的控制位跨 opcode 复用性判断）。
2. `mul` 是 `fma` contraction 的天然对照组：同一对操作数分别走 `mul`+`add` 两条指令与走单条 `fma` 时，是否存在与 F32 类似的收缩优化（在 STATIC_ONLY 范围内只需确认 SASS 指令数是否减少，不判定数值行为）。

### `fma`（A / A''，套件已建，`FRAMEWORK_VALIDATED`）

1. 核心发现已写入"结论"与助记符表：标量路径按舍入 token 分叉（`.rn`→原生，`.rz/.rm/.rp`→F32 模拟），packed 路径不分叉。这是全族最值得后续深挖的机制——需要在 `06_cuda_core_fp` 的 f32 fma 结论基础上，交叉验证模拟路径的 `FFMA.RZ/RM/RP` 是否与直接写 f32 fma 得到的指令编码完全一致（若一致，说明 ptxas 把 `fma.rz.bf16` 处理为"提升到 f32 计算+收窄"的通用降级策略，而非 bf16 专属代码路径）。
2. `.sat`/`.ftz` 在两条路径上都非法，已作为复合抽样探针钉死，但尚未验证是否存在其他舍入模式以外的路径分叉（如极端操作数触发的额外指令,当前套件的 STATIC_ONLY 范围不覆盖）。
3. `template_wide`/`producer_indirect`/`lane_asymmetric_pack`/`chain`/`guarded`/`consumption_distance`/`parallel_depth` 七条上下文轴已进 expanded，覆盖 P0-1/P1-1/P1-2 与"双 fma 链"完成门槛项；尚未覆盖的是深度 > 4 的在飞并发（当前套件到 4）。

### `min` / `max`（A，套件待建）

1. `.abs`/`.xorsign` 互相要求的语法约束已钉死，且已验证四种合法组合（`{}`/`.NaN`/`.abs.xorsign`/`.abs.NaN.xorsign`）的独立 SASS 编码；尚未验证的是 `.abs.xorsign` 组合下 `|a|` 操作数修饰符是否也能同时搭配立即数操作数（当前只用寄存器操作数探测过）。
2. `min`/`max` 共享同一 `HMNMX2.BF16_V2` 单元、仅谓词极性不同——需要确认该谓词是否可被外部条件替换（即 `min`/`max` 在控制字层面是否是同一个"可参数化方向"的原语，还是纯粹的编译期助记符选择）。

### `abs` / `neg`（A'，套件待建）

1. 核心发现：均无独立 SASS opcode，靠 `HFMA2.BF16_V2` 恒等式合成；且 PTX 层面 `neg`+`add` 两条指令不会被融合成 `add` 的取负操作数编码（O0/O3 均验证）。这对"逆向规则挖掘"有直接影响：见到独立的 `HFMA2.BF16_V2 Rd,-RZ,RZ,{±|Ra|}` 序列时，无法从编码本身区分它来自 `abs`/`neg`（各自唯一决定），还是理论上可能来自"完全未使用 a、b 操作数的退化 `fma`"（在合法 PTX 语义下不会出现，但作为逆向候选集合的假警报风险应在规则挖掘报告里注明）。
2. `abs`/`neg` 是否有 `.bf16x2` 下逐 lane 独立生效的证据（而非整字操作）需要非对称 lane 输入验证，当前探针仅用同值常量,需要后续套件补非对称输入。

### `set`（A，套件待建）

1. dtype 枚举已实测收窄到 `{u16,s16,u32,s32,bf16,bf16x2}`，`f16/f32/f64/u64` 全部拒绝——这是"读规范会画宽"的实例，套件设计必须以此为准而非通用 `set` 语法表。
2. `.bf16` dtype（浮点布尔输出）走"整型比较+`IABS`/`PRMT`/`I2F.BF16.S16`转换"三指令后处理序列，`target_patterns` 设计需要同时覆盖 `HSET2.BF16_V2` 与该后处理序列，否则会漏记这条路径的完整语义;`.bf16x2` dtype 则直接在 `HSET2` 助记符加 `.BF` 后缀，硬件级完成、无后处理——两种"浮点布尔输出"的实现代价不同，必须分别登记。
3. 3 操作数 `.BoolOp` 形式（`d,a,b,c`）已确认合法，`c` 操作数（谓词）未初始化时也能通过静态编译（语义未定义但语法合法）；套件需要显式初始化该谓词以保持负向探针诊断的可归因性。

### `setp`（A，套件待建）

1. 双谓词 `p|q` 形式在 lane 值互异且两谓词都被消费时，编译成**单条** `HSETP2.BF16_V2` 同时产出两个谓词，后接 `PLOP3.LUT` 归一化——套件的 `target_patterns` 需要同时覆盖 `HSETP2.BF16_V2` 与 `PLOP3.LUT`（后者也会被其他谓词逻辑合成路径命中，需要用消费者结构收窄误命中风险）。
2. 退化探针（两 lane 同值或某谓词未消费）会让编译器只对一个 lane 做比较,这是一个已知坑，套件设计必须坚持"lane 值互异 + 两谓词都消费"才能观测到真正的双输出语义,已写入本文档"已校准合法面"一节，供后续套件直接复用而不必重新踩坑。

## 边界声明

全部结论为 `STATIC_ONLY`：编译通过 + 归属成功不证明数值舍入正确性、NaN/±0 语义、饱和裁剪行为或任何运行时可见的浮点结果。`fma.rz/.rm/.rp.bf16` 标量路径"走 F32 模拟序列"这一发现只是**指令选择层面的静态观测**，不构成"该路径产出的舍入结果在数值上正确"的声明——按项目口径，运行时语义验证不在本族范围内。所有立即数值（`0x3F80` 等）仅作为编译期占位输入，用于触发确定性的指令选择,不代表对这些具体比特模式的数值行为做出任何断言。跨版本重跑：本文档与 `fma` 套件均只锚定单一工具链二进制（ptxas V13.0.88 / nvdisasm V13.0.85）,套件的 `check_all.sh` 通过 `check_cases.py`/`check_negative_probes.py` 的 `--ptxas`/`--nvdisasm` 参数支持换版本重跑,尚未做跨 release 差分。
