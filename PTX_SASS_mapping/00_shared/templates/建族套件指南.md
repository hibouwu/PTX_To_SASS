# 指令族实验设计与套件建设指南

> 目的：让任何一个指令族按同一质量标准产出"能通过对抗式审查"的实验设计和可运行套件。
> 质量标准源自 `01_tcgen05/对抗式审查_实验设计缺口.md`；结构范例是 `02_tma/`（实验设计.md + 两个 `FRAMEWORK_VALIDATED` 套件）。

## 交付物（每族）

1. `<family>/实验设计.md`：结构分类、**实测**助记符表、已校准合法面、审查缺口对应设计、每指令研究重点、套件路线图、`STATIC_ONLY` 边界声明。
2. 至少一个旗舰 opcode 的自包含套件 `<opcode>/thor_ptx90/`，`./check_all.sh` 全绿。
3. 族 README 与旗舰 opcode README 状态更新（`NOT_STARTED` → `FRAMEWORK_VALIDATED`/`DESIGNED`，附套件链接与一句话实测映射摘要）。

## 流程

1. **先校准，后设计**。在 scratchpad 写探针 kernel（`.version 9.0` / `.target sm_110a`），用 `/usr/local/cuda/bin/ptxas -arch=sm_110a -O0/-O3` 编译、`nvdisasm --print-code --print-instruction-encoding` 反汇编。设计文档里的每一张映射表、每一条合法面结论都必须来自探针或套件运行，不得来自规范阅读。规范阅读得出的预期若与实测冲突，以实测为准并把冲突写进文档（这是 P0-2 要求的证伪记录）。
2. 复制 [`suite_runtime.py`](suite_runtime.py) 原样进 `<opcode>/thor_ptx90/`，写本 opcode 的 `suite_spec.py`（`Spec(family=..., opcode=..., ptx_opcode=..., target_patterns=..., ...)`），加五个 8 行 wrapper（`generate_cases.py`/`validate_generated.py`/`check_cases.py`/`check_negative_probes.py`/`analyze_mapping_rules.py` 分别调 `cli_generate`/`cli_validate`/`cli_check`/`cli_negative`/`cli_analyze`）、`check_all.sh`、`results/.gitignore`（`*` + `!.gitignore`），套上与 `02_tma/cp.async.bulk.tensor/thor_ptx90/` 相同的五步流水线。
3. 跑 `./check_all.sh`，按真实失败迭代 `suite_spec.py`：预期合法却被拒 → 移入负向并登记诊断；预期非法却通过 → 这是发现，移入正向并写进设计文档。
4. 全绿后写文档与 README。

## 对抗式审查检查单（缺一即不合格）

| 缺口 | 套件里的最低落实 |
|---|---|
| P0-1 控制位是全局资源 | expanded 含在飞深度（≥2 档）与消费距离轴；runtime 已保留全函数 128-bit 编码（`full_instructions`），文档声明控制字差分数据就绪 |
| P0-2 合法面未证伪 | 每条负向探针登记 `expected_diagnostic` 子串（**先探针取真实诊断再登记**，不同约束的诊断文本可能不同）；另设 ≥2 条假定合法面之外的补集抽样探针；"预期非法却编译通过"记为发现渠道 |
| P0-3 组合不足 | 修饰符组合不只做单因素：至少覆盖已校准的双修饰符组合；协议类指令以序列上下文（深度 × 距离 × 类型混合）为主轴 |
| P1-1 模板未受控 | expanded 含 `template_wide` case（加宽/打乱参数签名） |
| P1-2 重物化前提 | 关键操作数各有 indirect producer case（从内存装载/计算得出，不可折叠） |
| P2 边界 | 文档含 `STATIC_ONLY` 声明与跨版本重跑说明（套件接受 `--ptxas/--nvdisasm` 路径参数） |

## 已知坑

- 寄存器命名不得与特殊寄存器同名（`%tid`、`%ctaid` 等会撞名，用 `%t0` 类名字）。
- 每个 case 必须有消费者（结果 `st.global` 或经 `xor` 汇聚后落地），否则 O3 会消除目标指令；副作用指令（st/atom/异步拷贝）除外。
- `target_patterns` 是子串匹配，注意过匹配：`BAR` 会同时命中 `MEMBAR`/`DEPBAR`/`BAR.SYNC`；kernel 尾部恒有 `BRA (.L_x_0)` 循环跳转，任何含 `BRA` 的匹配都会误命中。选更长的助记符前缀，或据此换旗舰。
- 合法但零指令的 lowering（fence 类、可折叠 mov 等）用 `empty_target_allowed` 按坐标放行，并在文档按 tcgen05 D 类处理：观测量换成相邻指令控制字。
- 一对多 lowering（一条 PTX 展开成序列）是合法形态，`target_patterns` 放多个助记符即可；归属计数以 pattern 命中集合为准。
- 负向探针的 module 必须除目标行外全部合法（寄存器、参数齐全），失败必须来自目标指令本身。
- **基线零命中检查**（ALU/访存类必做）：把脚手架（去掉目标行的同一 kernel）在 O0–O3 编译反汇编，确认 `target_patterns` 命中数为零后才冻结 spec。O0 会用 `IMAD.MOV` 当通用 mov、消费者 `xor` 会产生 `LOP3`，脚手架与目标同助记符时归属会被污染；对策是换消费者（直接 `st.global` 落地）或换更长的 pattern。
- `nvdisasm` 无 `--separate-functions` 时多函数会拼在一起——模板 runtime 已带该参数，别删。

## 状态口径

套件全绿 = `FRAMEWORK_VALIDATED`（静态实验闭环）；只有设计与校准 = `DESIGNED`；两者都不能声明运行时语义。族 README 的状态行必须写清首轮自检的 case 数与负向探针数。
