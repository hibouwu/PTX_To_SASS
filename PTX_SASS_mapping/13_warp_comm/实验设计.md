# Warp communication 族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。文中"实测"来自本机全 6 opcode 校准探针（shfl 全 mode/谓词/mask 形态、vote 四形态、match 四形态、redux 全 op、elect、activemask，各含 O0/O3 与发散上下文对照）与已建成旗舰套件 `shfl.sync/thor_ptx90/`（34 syntax + 46 expanded case，O0–O3 共 320 次编译/归属，6 个带诊断锚定的负向探针）的全量自检。探针在会话 scratchpad；套件 `suite_spec.py` 文档字符串同步记载校准结论。
> 设计基线：`01_tcgen05` 的静态实验分层与 `02_tma/实验设计.md` 的文档结构，逐条吸收 `01_tcgen05/对抗式审查_实验设计缺口.md` 的 P0/P1 结论。

## 结论

本族的核心结构事实有三条，均与"opcode → 助记符"直译模型冲突：

1. **membermask 不是 SHFL 的操作数**。PTX 的 membermask 在 SASS 层控制的是**是否在 SHFL 前发射 `WARPSYNC` 及其形态**：收敛点 + 立即数/可证明 uniform 的 mask → `WARPSYNC` 被省略（ptxas **不**静态校验声明的 mask 与实际活跃集一致）；不可证明 uniform 的运行时 mask（`%tid` 派生）→ 即使在收敛点也发 `WARPSYNC Rn`；真实发散之后 → 满掩码立即数发 `WARPSYNC.ALL`（无操作数）、部分/非满 mask 发 `WARPSYNC Rn`。`WARPSYNC` 在所有已测配置中从不取 UR 操作数——mask 的 uniformity 决定**是否发射**，不改变其寄存器类别。此机制与 `16_megakernel_ctrl/bar.warp.sync` 的 D′ 类结论互为印证（同一 `WARPSYNC` 家族、同一收敛分析开关）。
2. **uniform 源消除**：`a` 操作数可被编译器证明 warp-uniform（如参数直取）时，shuffle 是代数空操作，`SHFL` 整条消失——套件唯一的 `empty_target_allowed` 坐标（`uniform_source_elimination`）。与 `09_special_reg` 的 SHFL 消除观察交叉印证。
3. **collective 结果的 UR 路由**：`redux` 的目的寄存器**恒为 UR**（`REDUX.SUM.S32 UR6, R0`），`elect` 的 laneid 目的也是 UR（`ELECT P0, UR6, PT`）——warp-collective 结果被 ptxas 视为 uniform 值直接路由进 uniform 寄存器文件；`vote` 的谓词结果留在 P，ballot 的 mask 结果留在 GPR。GPR/UR/P 路由是本族 P0-1 的对应物。

## 合法面实测（负向探针）

| 探针 | 诊断 |
|---|---|
| 无 `.sync` 的旧式 3 操作数 `shfl` | "Instruction 'shfl' without '.sync' is not supported on .target sm_70 and higher from PTX ISA version 6.4"（诊断内嵌版本史） |
| `shfl.sync.up.b64`（数据宽度） | "Unexpected instruction types specified for 'shfl'" |
| mask 槽放 `.f32` 寄存器 | 类型错配诊断 |
| 补集：`u32` 类型 token、缺 c 操作数、谓词槽类型错 | 各自独立诊断（3 条补集抽样） |

## 审查缺口对应设计

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | 对应物是 **GPR/UR/P 路由**与 **WARPSYNC 发射决策**：两者都由区域级 uniformity/收敛分析决定而非指令语法；套件的 mask 轴（满立即数/部分立即数/uniform 寄存器/非 uniform 寄存器 × 收敛/发散点）就是该决策面的系统采样 |
| P0-2 合法面未证伪 | 6 条负向探针全带 `expected_diagnostic`（含 3 条补集）；"ptxas 不校验 mask 与活跃集一致"与"可证明常量寄存器折叠回立即数"是两条被证伪后修正的假设，已写进套件设计（后者迫使寄存器轴改用 `%tid` 派生值） |
| P0-3 组合不足 | mode × 谓词目的 × b/c 操作数类 × mask 类的组合矩阵（34 syntax case）；expanded 追加发散上下文 × mask 类的交叉（WARPSYNC 形态表的来源）与 shfl 链（结果喂第二个 shfl） |
| P1-1 模板未受控 | expanded 含 `template_wide` |
| P1-2 重物化前提 | lane 源 `a` 与 b/c 各有间接 producer case；`uniform_source_elimination` 是"可重物化导致指令消失"的显式记账 |
| P2 边界 | 套件接受 `--ptxas/--nvdisasm` 路径参数；WARPSYNC 发射决策依赖 ptxas 收敛分析，是跨版本最可能漂移的部分 |

## 各指令研究重点

- `shfl.sync`（`FRAMEWORK_VALIDATED`）：套件见 [shfl.sync/thor_ptx90/](shfl.sync/thor_ptx90/)；后续轴是 clamp 段（c 操作数）的编码语义与 `.b32` 上限之外的宽数据模拟序列。
- `vote.sync`（`DESIGNED`）：四形态映射已校准（`.uni`→`EQ`、ballot→GPR 目的 `VOTE.ANY`）；套件重点是谓词极性（`!P` 折叠）与发散上下文。
- `match.sync`（`DESIGNED`）：`MATCH.ANY/ALL[.U64]` 已校准；`all` 的双目的（Pd+Rd）归属结构是套件设计要点。
- `redux.sync`（`DESIGNED`）：UR 目的是结构事实；op→修饰符表（add→SUM、and→全缺省、u32 缺省/s32 显式）需全 op 枚举补完；f32 形态（PTX 9.0 若合法）待探。
- `elect.sync`（`DESIGNED`）：单形态指令，套件价值在与 tcgen05 alloc 序列 `ELECT` 的编码对比与谓词消费结构。
- `activemask`（`DESIGNED`）：无专用指令（`VOTE.ANY PT`），套件需用 `VOTE` pattern 归属并声明与 vote 套件的归属边界。

## STATIC_ONLY 边界声明

本文与套件的全部结论限于静态编译与反汇编。collective 的参与集合语义、mask 与实际活跃集不一致时的行为（ptxas 不静态校验，属运行时未定义面）、收敛前提的违反后果，都需运行时验证；族 README 要求的"违反 collective 前提的 case 单独负向记账"在静态层只能覆盖语法可拒绝的子集，其余记入运行时负向 corpus 待建。
