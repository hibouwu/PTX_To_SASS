# Megakernel control 族实验设计

> 适用范围：PTX ISA 9.0、NVIDIA Thor、`sm_110a`、CUDA 13.0（ptxas V13.0.88、nvdisasm V13.0.85）
> 本文性质：实验设计裁决 + 首轮校准记录。文中"实测"来自本机 50 个校准探针（`bar.warp.sync` 22 个、`nanosleep` 2 个、`griddepcontrol.*` 5 个、`prefetch.*` 7 个、`clusterlaunchcontrol.*` 12 个、基线脚手架 1 个）的 O0–O3 编译反汇编，以及已建成套件 `bar.warp.sync/thor_ptx90/`（44 case）O0–O3 全量自检。校准探针脚本在会话 scratchpad，套件可重现全部结论。
> 设计基线：`01_tcgen05` 的静态实验分层（syntax/expanded/negative/O0–O3/归属/规则挖掘）与 `02_tma` 的分类法，逐条吸收 `01_tcgen05/对抗式审查_实验设计缺口.md` 的 P0/P1 结论。

## 结论

本族 7 个 opcode 全部合法（**没有一个在 `sm_110a` 上被拒绝**，包括规范阅读容易误判为"实验性/不可用"的 `clusterlaunchcontrol.*`），但落在四种不同的 PTX→SASS 结构类别，比 TMA 族更不均匀：

| 类别 | 指令 | PTX→SASS 结构 |
|---|---|---|
| A 单指令直译（跨 O0–O3 稳定） | `nanosleep.u32`、`griddepcontrol.wait`、`griddepcontrol.launch_dependents`、`prefetch.global.{L1,L2,L2::evict_last}` | 1 条 PTX → 1 条 SASS，O0–O3 恒定出现，无消费者也不被消除（副作用指令） |
| D′ 语境相关零指令（本族新现象，非 tcgen05 已见的"恒零"D 类） | `bar.warp.sync`（**无 guard** 时） | O0 恒产生 `WARPSYNC.COLLECTIVE`+`ENDCOLLECTIVE`；O1–O3 在本文测过的全部上下文（含真实 warp 分支分歧、循环携带分歧、跨 lane 数据依赖、部分 mask、间接 mask、mask 后 `exit` 幸存子集同步）中**全部被消除为零指令**——因为 ptxas 自身的 `BSSY.RECONVERGENT`/`BSYNC.RECONVERGENT` 收敛括号已经证明该 barrier 冗余 |
| A（同一 opcode 的第二种存活形态） | `bar.warp.sync`（**有 guard** `@%p` 时） | 谓词化后在 O0–O3 全部materialize：mask 为编译期已知全掩码 `0xffffffff` → `WARPSYNC.ALL`（裸操作数，与 `01_tcgen05` alloc/dealloc 序列中自动插入的 `WARPSYNC.ALL` 是**同一条 SASS 助记符**，已交叉核对）；mask 为部分立即数或寄存器 → `WARPSYNC Rn` |
| B 编译器合成协议（无 1:1 opcode） | `clusterlaunchcontrol.try_cancel` | 多条 SASS 组成的工作窃取协议：`SYNCS.EXCH.64`（mbarrier 交换）+ 谓词簿记（`PLOP3.LUT`/`ELECT`）+ `UGETNEXTWORKID.SELFCAST`（真正的硬件工作窃取原语，唯一具名锚点）+ `WARPSYNC.ALL` + `BAR.SYNC.DEFER_BLOCKING` |
| E 吸收进通用 ALU（无专属助记符，本族新增类别） | `clusterlaunchcontrol.query_cancel` | `.is_canceled` 与 `.get_first_ctaid::{x,y,z}`/`.v4` 全部编译为对 `.b128` 寄存器内容的普通位运算（`LOP3.LUT` 位测试、`SHF.R.U32.HI` 位段提取），**没有任何专属 SASS 助记符**可用作 `target_patterns` |

D′ 类是本族对 tcgen05 分类法的实质扩展：tcgen05 的 D 类（fence 等）是"任何上下文都不产生指令"；本族的 `bar.warp.sync` 是"是否产生指令取决于 ptxas 能否用自己的控制流收敛分析证明该 barrier 冗余"——guard 谓词是已确认的唯一开关（详见下节）。这本身回应了 P0-3："控制位是否被移动/消除"必须用序列上下文回答，不能只看单指令语法。

## 实测助记符总表

### `bar.warp.sync`（D′ / A，套件已建，`FRAMEWORK_VALIDATED`）

| PTX 形式 | O0 SASS | O1–O3 SASS（无 guard） | O1–O3 SASS（`@%p` guard） |
|---|---|---|---|
| `bar.warp.sync 0xffffffff;`（立即数满掩码） | `WARPSYNC.COLLECTIVE Rn, target` + `ENDCOLLECTIVE` | **零指令**（消除） | `WARPSYNC.ALL`（裸操作数） |
| `bar.warp.sync %mask;`（寄存器，含间接产生的 mask） | 同上 | 零指令 | `WARPSYNC Rn` |
| `bar.warp.sync 0x0000ffff;`（立即数部分掩码） | 同上 | 零指令 | `WARPSYNC Rn`（mask 物化进寄存器） |
| `bar.warp.sync 0x0;`（零掩码，边界值） | 同上 | 零指令 | 未测（复合探针未做，推断同部分掩码路径） |
| 两条相邻 `bar.warp.sync`（无 guard） | 各自 `WARPSYNC.COLLECTIVE`×2 | 零指令 | — |
| 两条相邻 `@%p bar.warp.sync`（guard，合并观察） | — | — | **不合并**：O3 产生两条独立 `WARPSYNC.COLLECTIVE Rn, target`（改用 `BRA.DIV` 分支而非单 guard 的 `@P0 BRA`），结构与单条 guard 的 `WARPSYNC.ALL` 形态不同——证明"guard 数量"本身是影响 lowering 形态的组合轴，不是单纯复制 |

消除机制实测（`probe:p11/p16/p17/p18`，见下节"消除条件"）：即使构造真实 warp 分歧（数据依赖循环 trip count、跨 lane 读邻居写入的数据、`atom.global` 副作用阻止 if-conversion、谓词化 `exit` 后对幸存子集同步），只要 `bar.warp.sync` 本身不带 guard，O1–O3 均消除；O0 反汇编显示 ptxas 会为**真实**divergent 分支单独插入 `BSSY.RECONVERGENT`/`BSYNC.RECONVERGENT`，说明 O1+ 消除的依据是"该收敛括号已经建立了 barrier 要求的会合点，显式 `bar.warp.sync` 不再提供额外信息"。这是一个可证伪、可复现的结论，不是未观察到消除的假设。

消除开关：guard 谓词（`@%p bar.warp.sync ...`）。guard 把指令变成"是否执行"本身依赖运行时谓词的条件分支（`@P0 BRA` 跳过 WARPSYNC），产生跳过/不跳过两条路径不对称会合的真实分歧，ptxas 无法再用静态收敛证明消除它，因此 guard 后的 `bar.warp.sync` 在 O0–O3 全部materialize。这是本套件正向矩阵的主轴。

访存位置对照（P0-3 双向对照，`probe:n10-n13`）：在 guard 存活形态下，`WARPSYNC.ALL`/`WARPSYNC Rn` 相对其前后的 `STS`/`LDS` 未观察到被吸收或移动——四种前后 shared 访存组合（无/前/后/前后）里，`WARPSYNC` 都留在源代码对应的程序位置，访存顺序不变。这是一个否定性发现（未发现移动），已按 P0-3 要求写入负向证据。

### `nanosleep.u32`（A）

| PTX | SASS |
|---|---|
| `nanosleep.u32 100;`（立即数） | `NANOSLEEP 0x64` |
| `nanosleep.u32 %d;`（寄存器） | `NANOSLEEP Rn` |

O0–O3 恒定出现，与 `01_tcgen05` alloc 自旋重试路径里观察到的 `NANOSLEEP 0x64` 退避一致（交叉核对：都市同一条 SASS 助记符，`tcgen05` 是编译器自动插入，这里是显式 PTX）。负向：`nanosleep.u64` → `Unexpected instruction types specified for 'nanosleep'`（类型受限于 `.u32`）。

### `griddepcontrol.wait`（A）

`griddepcontrol.wait;` → `ACQBULK`，O0–O3 恒定，无操作数。负向：附加操作数 → `Arguments mismatch for instruction 'griddepcontrol'`。

### `griddepcontrol.launch_dependents`（A）

`griddepcontrol.launch_dependents;` → `PREEXIT`，O0–O3 恒定，guard 谓词合法。与 `griddepcontrol.wait` 同一 kernel 组合（典型 persistent-kernel 用法：wait → compute → launch_dependents）时，`ACQBULK ... STG ... PREEXIT ... EXIT` 的相对顺序与源码一致，未观察到重排。

### `prefetch.global.{L1,L2}`（A，含 `::evict` 变体）

| PTX | SASS |
|---|---|
| `prefetch.global.L1 [a];` | `CCTL.E.PF1` |
| `prefetch.global.L2 [a];` | `CCTL.E.PF2` |
| `prefetch.global.L2::evict_last [a];` | `CCTL.E.PML2`（**独立助记符**，不是 `.PF2` 加后缀） |
| `prefetchu.L1 [a];`（uniform 数据通路） | `CCTL.E.PF1`（与 `prefetch.global.L1` 同助记符，未观察到区分） |
| `prefetch.local.L1 [a];`（越界参考，非本族但同源指令） | `CCTLL.PF1`（独立前缀 `CCTLL`，与 global 的 `CCTL` 区分 state space） |

零指令假设被推翻：即使 `prefetch` 后没有任何消费该地址的 `ld`（`probe:p21`，standalone），O0–O3 仍然保留 `CCTL.E.PF1`——`prefetch` 与 TMA 族的异步拷贝同属"副作用指令"，不受消费者折叠规则约束，不需要 `empty_target_allowed`。负向：省略 cache level → `Cache level modifier required for instruction 'prefetch'`；`.L1::evict_last` → `Modifier '.evict_last' requires cache level L2 with 'prefetch' instruction`（evict 优先级只对 L2 开放）。

### `clusterlaunchcontrol.try_cancel`（B，`sm_110a` 合法，非拒绝）

语法（已校准，`.b128` 是必需的响应宽度，`.u64`/两个 `.u64` 都不能替代）：

```ptx
clusterlaunchcontrol.try_cancel.async.shared::cta.mbarrier::complete_tx::bytes.b128 [addr], [mbar];
clusterlaunchcontrol.try_cancel.async.shared::cta.mbarrier::complete_tx::bytes.multicast::cluster::all.b128 [addr], [mbar];
```

lowering（O0 与 O3 结构一致，只是谓词生成方式不同：O0 用 `PLOP3.LUT` 显式布尔代数，O3 额外插入 `ELECT`）：

```
SYNCS.EXCH.64 URZ, [mbar_UR], value_UR   // mbarrier 到达/交换
PLOP3.LUT ...                            // 谓词簿记（O3 另加 ELECT P1）
UGETNEXTWORKID.SELFCAST [resp_UR], [ctx_UR]   // 唯一具名硬件原语：工作窃取取号
WARPSYNC.ALL
BAR.SYNC.DEFER_BLOCKING 0x0
```

`UGETNEXTWORKID` 是本条指令唯一可用作归属锚点的助记符；`SYNCS.EXCH.64`/`WARPSYNC.ALL`/`BAR.SYNC.DEFER_BLOCKING` 在其他协议里也出现（分别是 mbarrier 族、warp barrier 族、CTA barrier 族的通用组件），单独出现不能反推是 `try_cancel`。负向：状态空间写成 `.global`（应为 `.shared::cta`）→ `State space incorrect for instruction 'clusterlaunchcontrol.try_cancel.async'`。

### `clusterlaunchcontrol.query_cancel`（E，`sm_110a` 合法，非拒绝）

语法（已校准；规范阅读的一个常见错误是把类型写成 `.u32`，正确是 `.b32`）：

```ptx
clusterlaunchcontrol.query_cancel.is_canceled.pred.b128 %p, %resp;
clusterlaunchcontrol.query_cancel.get_first_ctaid::x.b32.b128 %x, %resp;   // ::y、::z 同构
clusterlaunchcontrol.query_cancel.get_first_ctaid.v4.b32.b128 {%x,%y,%z,%w}, %resp;
```

lowering：`is_canceled` → `LOP3.LUT P0, RZ, R_hi, 0x1, RZ, 0xc0, !PT`（对 `.b128` 高 64 位字取位 0）；`get_first_ctaid::{x,y,z}`/`.v4` → `LOP3.LUT`（低 16 位掩码）+ `SHF.R.U32.HI`（高 16 位位段提取），均作用于低 64 位字。**没有专属 SASS 助记符**：整条指令族被编译器完全吸收进通用位运算，`LOP3.LUT`/`SHF.R.U32.HI` 在任何 kernel 里都可能因为完全无关的位运算出现，不能作为 `target_patterns` 使用而不产生大量误命中（对应指南"已知坑"里 `BAR`/`MEMBAR` 过匹配的同类问题，这里更极端——没有专属前缀可换）。归属唯一可行路径是绑定紧邻的立即数操作数（`0x1`、`0xc0`、`0xffff`、`0x10`），脆弱且超出本轮范围，留给后续套件。静态层还确认：在没有先检查 `is_canceled` 的情况下直接调用 `get_first_ctaid` 依然编译通过（`probe:neg_clc_query_before_check`）——这是文档规定的运行时协议要求（"先查是否被取消，否则未定义"），不是静态约束，进一步印证 STATIC_ONLY 边界。

## 合法面实测（负向探针诊断，先取真实诊断再登记）

| 探针 | 诊断（原文子串） |
|---|---|
| `bar.warp.sync` mask 为 `.b64` 寄存器 | `Arguments mismatch for instruction 'bar.warp'` |
| `bar.warp.sync` mask 为 `.f32` 寄存器 | 同上 |
| `bar.warp.sync` mask 为 `.pred` | 同上 |
| `bar.warp.sync` mask 为 `.b16` 寄存器 | 同上 |
| `bar.warp.sync` 缺操作数 | 同上 |
| `bar.warp.sync` 多一个操作数 | 同上 |
| `nanosleep.u64`（类型越界） | `Unexpected instruction types specified for 'nanosleep'` |
| `griddepcontrol.wait` 附加操作数 | `Arguments mismatch for instruction 'griddepcontrol'` |
| `prefetch.global`（缺 cache level） | `Cache level modifier required for instruction 'prefetch'` |
| `prefetch.global.L1::evict_last`（evict 优先级配 L1） | `Modifier '.evict_last' requires cache level L2 with 'prefetch' instruction` |
| `clusterlaunchcontrol.try_cancel...global...`（状态空间错误） | `State space incorrect for instruction 'clusterlaunchcontrol.try_cancel.async'` |

两个被校准推翻的假设（P0-2 补集抽样，"预期非法却编译通过"）：

1. `bar.warp.sync 0x0;`（零掩码）——规范阅读容易假设"同步空集合"是非法或至少是 UB 会被拒绝的边界，实测 ptxas 照常接受并在 O0 产生正常的 `WARPSYNC.COLLECTIVE`。
2. `@%p bar.warp.sync mask;`（谓词化 warp barrier）——`bar.sync` 系列常被认为"barrier 不能被 guard"（发散风险），实测 PTX/ptxas 都接受，而且这是本指令在 O1+ **唯一**存活的形态，是全套件最重要的一条正向证据，不是边角案例。

`clusterlaunchcontrol.*` 整体也是一次被推翻的假设：任务书要求"被拒则登记诊断为合法面发现"，但实测两条指令在 `sm_110a` 上都被**接受**且产生结构完整的 SASS（`try_cancel` 走多指令协议，`query_cancel` 吸收进 ALU）。合法面的发现方向因此反过来——真正的意外不是"被拒绝"，而是"规范阅读给出的类型签名（`.u64`/`.u32`）与 ptxas 实际接受的签名（`.b128`/`.b32`）不一致"，这本身就是 P0-2 要求记录的证伪案例。

## 对抗式审查缺口在本族的落实

| tcgen05 缺口 | 本族对应设计 |
|---|---|
| P0-1 控制位是全局资源 | `bar.warp.sync` 套件的 `context` 轴覆盖前后 shared 访存有无（4 种组合）、guard 数量（0/1/2）、mask 来源（立即数满/立即数部分/寄存器/间接 producer）；runtime 保留全函数 128-bit 编码（`full_instructions`），控制字差分不需要重跑实验 |
| P0-2 合法面未证伪 | 负向探针登记 `expected_diagnostic` 子串（本文已先取真实诊断）；`clusterlaunchcontrol.*` 全族属于"预期可能被拒"之外的补集抽样，结果整体推翻为合法；`bar.warp.sync` 另有零掩码与 guard 两条补集样本 |
| P0-3 组合/序列不足 | 本族的核心 P0-3 问题被重新表述为"控制指令相对前后访存/屏障的位置是否被 ptxas 移动"：`bar.warp.sync` 套件用双向对照（同一 guard 形态 × 前/后/前后 shared 访存的四种排列）直接回答，而不是假设式陈述；双 guard 相邻的合并观察证明"guard 数量"本身进入组合矩阵，不能被单指令语法覆盖 |
| P1-1 模板未受控 | `bar.warp.sync` 套件 expanded 含 `template_wide`（加宽/打乱参数签名）case |
| P1-2 重物化前提 | mask 操作数设 indirect producer case（`ld.global` 装载，不可折叠） |
| P2-1 单版本 | 套件与 TMA/tcgen05 相同接受 `--ptxas/--nvdisasm` 路径参数，跨版本差分只需换工具链重跑 |

## 每指令研究重点

### `bar.warp.sync`（套件已建，`FRAMEWORK_VALIDATED`）

1. guard 是否为唯一消除开关已用 8 种独立上下文验证（无分支、可 if-convert 分支、真实数据依赖循环分歧、跨 lane 读邻居、原子副作用、谓词化 `exit` 后子集同步、双重 sync、间接 mask）——全部一致；仍然遗留的问题是"是否存在**不需要 guard**也能强制materialize 的构造"（例如跨函数调用边界、`call`/`ret` 引入的隐式分歧），留给下一轮。
2. `WARPSYNC.ALL` 与 `01_tcgen05` alloc/dealloc 序列共享同一枚 SASS 助记符，说明 SASS 层"全 warp barrier"是统一原语，与 PTX 层来源（显式指令 vs 编译器合成协议）无关——这是可以反哺 tcgen05 文档的交叉发现。
3. 双 guard 相邻从 `WARPSYNC.ALL` 切到 `WARPSYNC.COLLECTIVE`+`BRA.DIV` 结构，说明"guard 数量 ≥ 2"应作为独立组合维度，而不是把"含 guard"当布尔轴处理完就够。

### `nanosleep.u32`（`DESIGNED`）

1. O0–O3 恒定出现且不受消费者折叠影响；下一步是退避序列层面的研究（循环内 `nanosleep` 幂次增长模式、与 `bar.warp.sync`/`atom` 自旋组合的调度习语），对应 tcgen05 alloc 自旋重试的"序列模板"研究方法。
2. 尚未校准：`nanosleep.u32 0`（零时长边界）、寄存器值来自 `atomicCAS` 类不可折叠 producer。

### `griddepcontrol.wait` / `griddepcontrol.launch_dependents`（`DESIGNED`）

1. `ACQBULK`/`PREEXIT` 均为无操作数单指令，O0–O3 恒定；组合探针证明 wait→compute→launch_dependents 的相对顺序被保留。
2. 尚未校准：guard 谓词对 `griddepcontrol.wait` 的影响（`launch_dependents` 已确认合法，`wait` 未测）；`launch_dependents` 多次调用（PTX 允许至多一次这一运行时约束是否有静态可观测的编译期差异）。
3. 运行时协议完成（grid 依赖是否真正建立/等待）明确排除在 `STATIC_ONLY` 之外——这是 README 里"指令被执行/协议完成/性能收益"三分口径在本指令上最直接的落地点。

### `prefetch.global`（`DESIGNED`）

1. `.L1`/`.L2`/`.L2::evict_last` 三种助记符已校准，且与 `01_tcgen05`/`02_tma` 不同：prefetch 是纯提示指令，standalone（无消费者）也不被消除，简化了套件设计（不需要 `empty_target_allowed`）。
2. `prefetch.local.L1` 与 `prefetchu.L1` 已顺带校准（分别是 `CCTLL.PF1` 与 `CCTL.E.PF1`），确认 state space 影响助记符前缀而 uniform 数据通路不影响。
3. 尚未校准：地址来自寄存器间接 vs 立即偏移是否改变编码；prefetch 距离实际 `ld` 的调度距离是否影响 `CCTL` 位置（代码移动风险，对应 README"重复/无用预取和代码移动"优先上下文）。

### `clusterlaunchcontrol.try_cancel`（`DESIGNED`）

1. 核心发现：`sm_110a` 完整支持该指令，lowering 是以 `UGETNEXTWORKID.SELFCAST` 为核心的多指令协议，与 `01_tcgen05` B 类（编译器合成协议）方法论直接适用。
2. `target_patterns` 建议以 `UGETNEXTWORKID` 为主锚点；`SYNCS.EXCH.64`/`WARPSYNC.ALL`/`BAR.SYNC.DEFER_BLOCKING` 需要归属到"协议组成部分"而非"本指令专属"，避免与 `03_mbarrier`/本族 `bar.warp.sync` 套件的归属冲突。
3. `.multicast::cluster::all` 变体已确认合法，尚未校准其对 `SYNCS.EXCH`/`UGETNEXTWORKID` 操作数形态的影响。

### `clusterlaunchcontrol.query_cancel`（`DESIGNED`）

1. 核心发现：整条指令族没有专属 SASS 助记符，完全吸收进 `LOP3.LUT`/`SHF.R.U32.HI` 通用位运算——这是本族对 tcgen05 分类法的补充案例（E 类），后续套件的目标归属必须绑定紧邻立即数操作数模式而非助记符子串，且需要显式声明"归属方法论本身是脆弱的"。
2. `.b128` 响应寄存器的位域布局（`is_canceled` 在高 64 位字 bit 0；ctaid 分量在低 64 位字，每分量 16 位）是**观测**，不是规范承诺，按 tcgen05 `decode_ctrl.py` 同等谨慎程度对待（"待 Thor 复核的假设"）。
3. 与 `try_cancel` 的响应必须走真实 mbarrier 完成协议（本文用 `bar.sync` 简化等待，静态层不校验完成语义）——运行时正确性完全排除在 `STATIC_ONLY` 之外。

## 三分口径声明（本族完成门槛的显式化）

本文与 `bar.warp.sync` 套件的全部 PASS 只证明**"指令被执行"**层（静态编译通过 + O0–O3 反汇编归属成功）。README 要求区分的另外两层明确排除在外：

- **"协议完成"**：`griddepcontrol.wait`/`griddepcontrol.launch_dependents` 是否真正建立/释放 grid 依赖，`clusterlaunchcontrol.try_cancel`/`query_cancel` 的 mbarrier 完成事务是否真正发生，`bar.warp.sync` 的 mask 是否与运行时实际活跃 lane 集合一致——这些都是运行时语义，`STATIC_ONLY` 不做任何断言。
- **"产生性能收益"**：`nanosleep` 的退避是否真正降低竞争、`prefetch` 是否真正减少后续 miss、`clusterlaunchcontrol.try_cancel` 的工作窃取是否真正改善负载均衡——静态实验不测量、不推断、不声明。

`STATIC_ONLY` 全部结论为：编译通过 + 归属成功不证明数据搬运、内存序、grid 依赖、mbarrier 完成或调度收益的可见语义。`.b128` cancel-response 的内部字段布局视为观测而非规范承诺（同 tcgen05 descriptor 的裁决方法论）。
